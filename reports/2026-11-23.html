Ghost-Downloader-3：回榜這天，不講協議全家福，講它怎麼當流程零件

XiaoYouChR / Ghost-Downloader-3 · GPL-3.0 協議 · Python · Windows／macOS／Linux／Android 四平台 · 提交 1,785 次 · fork 數 976 個 · 94 個發行版

插畫：Ghost-Downloader-3 今天的新看點在「可接線」——命令列、RPC、外掛三條路，都通向同一批下載任務。

一句話人話

號稱「下載器的集大成者」的開源下載器：一個 App 收下 HTTP、磁力／BT、FTP、M3U8、DASH、eD2k，YouTube 和 B 站還能選片段、選畫質、抓字幕。一天 +1,078 星、增幅 7.09%，總星 16,286——昨天它以 4.79% 落榜，今天新增比昨天多 388 星，增幅一次回到 7% 以上；11 月 20 日到 23 日四期抓榜新增合計 +3,624 星。

它到底是幹嘛的

協議全家福前兩期講過了，今天只講發稿前對照 README 剛核實過的三處「可接線」設計。第一，命令列跟圖形介面是同一套任務：ghd 工具在「設定 → 命令列工具」裡安裝，ghd probe <url> 先預覽不建任務，ghd add <url>... 建任務開下載，ghd tasks 列任務、ghd wait <taskId>... 等它下完——README 的範例就是先 ghd probe "https://example.com/a.torrent" 看裡面有什麼檔案，再 ghd add "https://example.com/a.torrent" --select 0,3 -o ./downloads 只抓第 0 和第 3 個檔案。第二，下載中途還能改：相容 aria2 的 RPC API 給第三方工具呼叫，下載進行中可以改連結、改標頭、改代理，進度不會丟——這句話 README 寫在功能清單裡，不是我們腦補的。第三，外掛路線圖寫在明處：Feature Packs 外掛生態已經在跑，路線圖下一步是把外掛 API 公開（API 還在穩定中），以及加強任務編輯、例如把多個 Session 綁到同一個任務。壞網路場景也還是它的招牌寫法：智慧分塊不用合併檔案、自動偵測頻寬、真實瀏覽器 TLS 指紋；瀏覽器擴充功能會在影片旁跟一個下載按鈕，登入狀態也能帶過去。平台覆蓋照舊是 Windows 10+、macOS 13.0+、Linux glibc 2.35+、Android 9.0+，Arch Linux 還有社群維護的 AUR 套件 ghost-downloader-bin 與 ghost-downloader-git。

它火在哪

一是「落榜一天就回來」本身就是訊號：昨天 +690 星已經不少，只是增幅卡在門檻下；今天 +1,078 星，說明昨天那批人不是看熱鬧，是真的在裝、在用、在推。二是它把「難下載」的場景講得很具體：爛網路、要換代理、下到一半要改連結——這些都是平常下載器最容易翻車的地方，README 不講「我們很快」，講「爛網路時我們怎麼辦」，反而讓人信。三是它沒有把自己關起來：aria2 相容 RPC、ghd 命令列、外掛 API 三條路都留著，別人不用換掉自己的工具鏈就能接它——工具活得久，往往就靠這種「讓別人接進來」的設計。

值得學什麼

最值得偷的是 「先預覽，再下手」：ghd probe 讓你在建任務之前先看清楚對方有什麼——我們工具站的榜單、報告流程也一樣：先給一個「只看不動」的預覽，再讓人決定要不要真的跑，翻車率立刻降下來。另一招是 「路線圖寫未完成的事，不裝已完成」：外掛 API 公開寫的是「進行中、API 還在穩定」，不先吹牛——讀者對這種老實話的信任，比對功能清單的信任更值錢。還有 「翻譯門檻寫死」：新語言要進 App，桌面文字翻譯要到 60% 才收——品質門檻先定好，後面才不用一遍遍返工。

先說清楚邊界：這是個下載工具，能下載什麼、該不該下載，要看內容本身的授權與平台規則——只抓自己有權取得的內容，別拿它去繞過付費牆、抓盜版或侵犯著作權。它本身不是惡意程式、詐騙、色情或政治敏感內容，所以照常入選；但怎麼用，是使用者的責任。
我們怎麼用：常寫腳本抓公開檔案的人（開源數據集、模型權重、工具站要用的公開資料），值得看 ghd 那套介面：ghd probe 預覽、ghd add --select 只抓要的檔案、ghd wait 等完再往下走——排程腳本照這個順序寫，半夜失敗了也知道卡在哪一步。對工具站來說，更值得帶走的是那句「爛網路時怎麼辦」：以後報告裡寫任何下載、抓取流程，先把網路差、要換代理、要斷點續傳的情況寫清楚，比只寫「很快」有用得多。

AutoClip：第四天了，講佇列、字幕分頁，和它老實交代的缺口

zhouxiaoka / autoclip · MIT 協議 · Python · 桌面版＋CLI＋MCP＋Docker · 提交 1,494 次 · fork 數 2,205 個

插畫：AutoClip 第四天的新看點不在新功能，在修復與缺口——佇列修好了，沒做的平台也先說清楚。

一句話人話

開源的 AI 影片剪輯桌面工具：貼一個長影片連結，選好要發的平台，自動剪出短影片，連字幕、封面和發文文案一起給你。一天 +908 星、增幅 6.75%，總星 14,366——連漲第四天，四天抓榜新增合計 +3,220 星，fork 數也從昨天的 2,124 個漲到 2,205 個。

它到底是幹嘛的

核心流程前三期講過了，今天只補發稿前對照 README 剛核實過的三處，都是「修復與缺口」這種平常不會放頭條、卻最能看出作者態度的內容。第一，最新正式版的修復清單：README 首段提醒，桌面、CLI 與 MCP 同步更新、版本以 autoclip --version 和 MCP 的 get_version 為準，提到的修復包括一鍵出片、字幕分頁、人物取景與長影片佇列——字幕怎麼斷行、人物怎麼取景、一次排多條長片會不會卡住，都是「剪出來能不能看」的細節，作者把它們跟新功能放同一句話裡講。第二，平台缺口老實寫：Intel Mac 目前沒有桌面安裝包，跟 Linux 一樣用 Docker 或 CLI；桌面安裝包目前未購置程式碼簽署／Apple 公證，新版本可能觸發 SmartScreen 或防毒誤報——這些話都寫在「快速開始」裡，裝之前就能看到，不用裝完才發現。第三，資料邊界照舊清楚：剪輯、取景與渲染在本機完成；用雲端分析會送出相關字幕與文案，畫面理解或參考幀生圖會送出抽樣畫面，雲端轉寫會送出音訊；匿名統計與錯誤報告可以在設定裡關掉。模型自己選：雲端 API、Ollama（預設 http://localhost:11434/v1）、LM Studio（預設 http://localhost:1234/v1）都行，桌面版還能先看內建的示例項目，不用 API Key。

它火在哪

一是連漲第四天，而且今天比昨天更兇：+640 星之後回到 +908 星，增幅從 5.01% 拉回 6.75%——貼線過關之後沒有洩氣，反而又漲回來，這種走勢比第一天爆紅更像「有人在真用」。二是它把「修復」當成賣點講：字幕分頁、人物取景、長片佇列，聽起來都不性感，但每一條都是使用者每天會撞到的地方——修這些，比加一個新平台更能留住人。三是缺口寫在前面：Intel Mac 沒包、沒簽署、可能誤報，先講清楚再讓人裝——這種老實，反而讓敢裝的人更敢在流程裡接它。

值得學什麼

最值得偷的是 「修復清單跟新功能放一起講」：我們的工具站改版也一樣，修了什麼、修到哪一步，寫得跟新功能一樣清楚，讀者才知道這東西還在被照顧，而不是發完就不管了。另一招是 「缺口寫在安裝之前」：哪個平台沒包、哪個環節會誤報，先寫在「快速開始」裡——讀者裝之前就知道邊界，裝完出問題也不會覺得被騙。還有 「版本以命令輸出為準」：桌面、CLI、MCP 三個入口同步更新，版本號不看文件寫的，看 autoclip --version 跑出來的——這種小紀律，是多入口專案最容易亂、也最值得抄的地方。

我們怎麼用：手邊有訪談、播客或課程長片、想一次排多條慢慢剪的人，先看 README 裡長片佇列那條修復說了什麼，再決定要不要升級；Intel Mac 或 Linux 機器，別等桌面安裝包，直接走 Docker：git clone https://github.com/zhouxiaoka/autoclip.git，再 cp env.example .env、docker compose up -d --build，部署細節以 README 的 Docker 指南為準。只剪自己有權使用的素材，別拿別人的成片去發。對工具站來說，今天最值得帶走的是那句「缺口寫在前面」：以後報告裡的新工具，先寫它不支援什麼，再寫它支援什麼。
