agent-desktop：昨天講了「怎麼看」，今天補上「怎麼接」

vercel-labs / agent-desktop · Apache-2.0 · Rust · macOS、Windows、Linux 皆可用 · 昨日基數 8,872 星

插畫：MCP 模式下，agent-desktop 從「手動跑的 CLI」變成「agent 工具箱裡的一組工具」，迴圈本身沒變。

一句話人話

如果昨天那期是「給 AI 一張桌面結構圖」，今天這期就是「把這張圖的用法，包成所有 agent 都會叫的標準工具」——不用再手動敲命令，agent 自己就能叫 desktop_snapshot、desktop_click 來操作桌面。

它到底是幹嘛的

先幫昨天沒看的人補一句：這是給 AI agent 用的電腦操作 CLI 與 C 函式庫，支援 macOS、Windows 和 Linux。它讀作業系統的無障礙樹、回傳 JSON，每個可操作元件都有編號（ref），agent 照編號行動、再快照驗證，全程不用截圖猜像素；而且 README 明寫：它裡面沒有模型，迴圈留在你的 agent 手裡。今天的新料有三件，都是對照 README 與昨日提交核實過的：第一，MCP 模式——agent-desktop mcp 會把每個命令都變成 MCP 工具（stdio），工具名就是命令名前面加 desktop_，例如 desktop_snapshot、desktop_click、desktop_session_start，接法就是一段 MCP 設定 JSON，指明命令 agent-desktop、參數 mcp；給 mcp 的全域旗標（例如 --session、--headed、--trace）會套用到每一次呼叫。第二，安裝多了一條路：macOS、Linux 上現在也能 brew install agent-desktop（README 同時提醒：官方不再維護自訂 Homebrew tap，也還沒有官方 Scoop 包，別裝錯來源）。第三，命令表本身沒變：60 個名字、56 個可實際操作，搭配 agent-desktop skills get desktop、skills get platform 這種隨二進位附帶的技能說明，以及 npx skills add 一行裝進 agent 工具箱的寫法。

它火在哪

第一，數字是真的在加速：昨日基數 8,872 星，一天 +3,792 星，增幅 42.74%——昨天已經是 30.63% 的大漲，今天新增數和增幅雙雙更高，是今天唯一同時過「新增 ≥300、增幅 ≥10%、基數 ≥1000」三關的專案。第二，MCP 這一步踩在點上：桌面操作工具最難的不是「能不能點」，而是「你的 agent 叫不叫得動它」；變成 MCP 工具後，門檻從「學一套 CLI」降成「加一段設定」，接進去的人自然變多。第三，維護節奏沒停：昨日提交包括 MCP 功能本身與 Homebrew 安裝文件整理，看得出是邊漲星邊補文件，不是丟上來就跑的演示。順帶一提，它昨天漲完今天又漲，連莊在這個專欄不是第一次（Hallmark 也曾連莊），榜單只認數字，不認「昨天講過就不能再講」。

值得學什麼

「把能力包成別人現成的工具」比「把能力做得更強」更容易傳開。agent-desktop 的核心（讀結構樹、按編號行動、再快照驗證）昨天就講完了，今天它什麼核心都沒換，只補了一個 MCP 包裝，漲勢反而更兇。對我們自己的工具站也是一樣的道理：一個檢查流程寫得再好，如果每次都要手動跑、還要先讀半天說明，就只有自己會用；包成「一行命令、一段設定就能接進現有流程」的樣子，別人才真的會拿去用。另一個值得偷的點是 README 的誠實：沒有模型就明說沒有模型、限制（快照可能含私人桌面內容、編號過期要重抓）寫在前面——限制先講清楚，用的人反而敢用。

我們怎麼用：昨天那期的試法仍然有效，而且今天多了一個更省事的接法：先在不放敏感資料的測試機上裝（npm install -g agent-desktop 或 brew install agent-desktop），如果你的 agent 支援 MCP，直接用 agent-desktop mcp 接進去，讓 agent 自己叫 desktop_snapshot、desktop_click 試一圈，比手動敲命令更快摸到手感。對工具站來說，真正要偷的還是那個驗證迴圈——以後寫自動檢查流程時，照著「每步行動後必須再看一次、證據過期就重抓」來設計。兩個紅線跟昨天一樣，先記住：README 明說快照、剪貼簿、截圖與命令輸出可能含私人桌面內容，絕對不要貼進公開日誌或上傳；也不要拿它去點交易軟體、做任何會動到真金白銀的操作——這期只是研究一個工具，不是叫你把它接上實盤。
