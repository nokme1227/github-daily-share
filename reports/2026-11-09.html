插畫：Astryx 內建七套主題，換主題就是換一組 CSS 變數，不用改元件、不必重包——設計師想換臉，改幾個變數就好。

一句話人話

Meta 把自家用了八年的「蓋頁面全套工具」端出來了：150 多個現成元件、七套主題、深色模式、模板，外加一個 CLI 管家——重點是它從一開始就假設「寫頁面的人一半是真人、一半是 AI」，所以人跟 AI 拿的是同一份說明書。

它到底是幹嘛的

一個開源設計系統，目前還在 Beta。它在 Meta 內部長了八年，是公司裡用得最廣、規模最大的設計系統，撐著 13,000 多個應用。裝起來不囉嗦：npm install @astryxdesign/core @astryxdesign/theme-neutral @stylexjs/stylex，再加 npm i -g @astryxdesign/cli 裝個全域 CLI（或在專案裡跑 npm run astryx -- component --list），引入預建好的 CSS、套上主題提供者就能用，不用另外裝建置外掛或 PostCSS、Babel 設定。需要 React 19 以上。裡面有 150+ 個無障礙元件、品牌級主題、深色模式、現成模板。README 裡特別強調四點不同：內部是開放的——元件可以任意層級組合，積木直接對外開放，需要更深時 swizzle 能把某個元件的完整原始碼彈進你的專案自己接手；不綁死樣式——它自己用 StyleX 寫樣式，但你可以用 Tailwind、CSS Modules 或純 CSS 蓋掉；換主題不用包一層——主題就是一組 CSS 自訂屬性覆寫，設計師不用 fork 也不用包元件就能把系統變成自己的；人跟 AI 共用同一套工具——API、文件、CLI 一起設計，讓真人和 AI 助手用同一個參考來蓋東西。

它火在哪

一是數字夠硬：一天 +3,324 星，增幅 19.99%，是今天全場唯一過 5% 增幅門檻的專案——絕對新增也排全場第二，只輸給 sherlock。二是昨天它才剛在榜上露過臉：11 月 8 日那期它一天 +863 星、增幅 5.47%，在舊的 10% 門檻下沒能進主榜；今天直接放量將近四倍，等於是連漲第二天，熱度不是一日遊。三是「agent-ready」這個賣點踩得正：從 Hallmark、Impeccable 到 agent-desktop，這一波漲得兇的專案有個共同點——都在回答「AI 寫東西越來越多，流程要怎麼跟上」。Astryx 的回答是乾脆把設計系統做成「人跟 AI 的共同語言」，這個敘事現在很有市場。

值得學什麼

「主題就是一組變數」這個做法可以直接偷。很多專案換主題要改一堆 class、甚至重包元件，Astryx 把主題收斂成 CSS 自訂屬性覆寫，換臉的成本降到改幾個變數——這跟我們工具站「配色收進變數、頁面只管引用」的方向是一回事，只是人家做得更徹底。第二，swizzle 的思路值得記下來：元件預設拿來就能用，但你隨時可以把它的完整原始碼彈出來自己改——「先給方便，再給自由」，比「要嘛全拿、要嘛自己寫」聰明。第三，文件、API、CLI 三件套一起設計：它說「讓 AI 更容易的改動，也讓人更容易」，這句話反過來讀就是——如果你的流程 AI 老是走歪，問題可能不在模型，在你的說明書寫得不夠清楚。

我們怎麼用：先潑一盆冷水：工具站是純靜態 HTML，沒有 React 建置鏈，直接把 Astryx 裝進來不划算，別為了追星重構整站。但它有三樣東西今天就能偷：第一，把工具站的配色、字級收進 CSS 變數，換主題只改變數檔，這正是 Astryx 主題系統的平民版；第二，學 swizzle 的「先給方便、再給自由」——工具站的共用片段（榜單表、卡片）做成可以直接複製改的範本，而不是只能整包引用的黑盒子；第三，把「人跟 AI 共用同一份說明書」落到實處：工具站的 PRODUCT.md、元件慣例寫清楚一點，下次 AI 改版才不會又把工具站做成 SaaS 落地頁。真想試它：找個有 React 19 的小專案跑 npm install @astryxdesign/core @astryxdesign/theme-neutral @stylexjs/stylex，再用 CLI 列元件玩玩看；記得它還在 Beta，別直接上生產環境。
