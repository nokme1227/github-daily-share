AutoClip：第五天，講 v1.6 的直播回放——直播結束，剪片就排隊

zhouxiaoka / autoclip · MIT 協議 · Python · 桌面版＋CLI＋MCP＋Docker · fork 數 2,266 個

插畫：v1.6 的重點是「回放變入口」——直播結束就排隊，剪完一鍵換平台再出。

一句話人話

開源的 AI 影片剪輯桌面工具：貼一個長影片連結，選好要發的平台，自動剪出短影片，連字幕、封面和發文文案一起給你。一天 +981 星、增幅 6.85%，總星 15,309——連漲第五天，五期抓榜新增合計 +4,201 星，fork 數也漲到 2,266 個。

它到底是幹嘛的

核心流程前四期講過了，今天只講發稿前對照 README 剛核實過的 v1.6「What's New」那張表。第一，直播回放變成正規入口：專門的 Live Replay 分頁支援 6 種來源——OBS Studio、Twitch、YouTube、Kick、Discord 與本機錄影檔，不再只是「貼連結」的一種。第二，OBS 自動擷取：接 OBS WebSocket（連接埠 4455），以無損裁切（-c copy）修剪，直播一結束就自動把片段排進佇列——人不用守在電腦前等匯入。第三，遊戲亮點有專門打法：亮點偵測支援 8 秒以上的獨立精彩片段，視覺／OCR 預算收得更緊——對話少的遊戲實況，README 建議開視覺模型。第四，一鍵換平台：同一張可播放的成品卡，換目標平台一鍵再出，不用重剪、之前出的版本不丟。第五，語言一次做到 13 種：桌面介面、托盤選單與文件都有 13 種語言，新增繁體中文、德文、印尼文、土耳其文、越南文，阿拉伯文字幕還支援 RTL 排版。基準數字也先說清楚再引用：README 自己貼的兩組實測是在 Apple Silicon Mac 上、用 qwen-plus 估算 LLM 成本、不含雲端轉寫與 AI 生圖，僅供參考、未經我們獨立驗證；剪輯與渲染在本機完成，雲端分析只送字幕文字、畫面理解只送抽樣畫面，雲端轉寫才送音訊，匿名統計可在設定裡關掉。

它火在哪

一是第五天還能回到 +981 星：連漲的走勢是 +983、+689、+640、+908、+981，中間貼線過關也沒洩氣，反而又漲回接近第一天的量——這種「跌回去再漲回來」比一直爆紅更像有人在真用。二是 v1.6 把場景從「剪完播客」擴到「直播結束就動手」：以前是人想起來才剪，現在是直播結束自動排隊——工具從「等你來用」變成「事情發生就接手」，這一步最容易留住直播主。三是「換平台不重剪」打中了發片人的痛：同一支片要發五個平台，以前是五次工，現在是一次工加四次一鍵——省下的不是時間，是「算了不發了」的那個念頭。

值得學什麼

最值得偷的是 「事件一發生就排隊」：別等使用者想起來，直播結束、檔案落地、任務完成——事件本身就是開工的號令，我們的報告流程也一樣，數據一到就該自動排隊，而不是等人去點。另一招是 「換輸出不丟舊輸出」：同一份內容出多種版本時，舊版本要留著、新版本要能一鍵重出，版本管理做在產品裡，別靠使用者自己在資料夾裡認檔名。還有 「語言與排版一次到位」：繁體中文與阿拉伯文 RTL 不是翻譯完就好，介面、托盤、文件、字幕排版要一起到——國際化是成套交付，不是事後補字串。

我們怎麼用：手邊有直播回放、訪談或課程長片的人，先用內建示例項目試一次、不用 API Key，確認流程合用再接自己的模型；要接 OBS 的話，按 README 的 Live Replay 分頁設定 WebSocket，直播結束看它是不是真的自動排隊。Intel Mac 或 Linux 機器別等桌面安裝包，直接走 Docker：git clone https://github.com/zhouxiaoka/autoclip.git，再 cp env.example .env、docker compose up -d --build，部署細節以 README 的 Docker 指南為準。只剪自己有權使用的素材，別拿別人的成片去發。對工具站來說，今天最值得帶走的是「事件一發生就排隊」加「換輸出不丟舊輸出」：榜單、報告、圖表同一份來源，多種輸出一次排好、舊版留檔。

Ghost-Downloader-3：輸了 0.05 個百分點，贏了絕對新增——今天講它的出身與手機那一面

XiaoYouChR / Ghost-Downloader-3 · GPL-3.0 協議 · Python · Windows／macOS／Linux／Android 四平台 · fork 數 1,049 個

插畫：Ghost 今天的新看點在手機與鏡像——Android 能錄直播、能背景下載，公開大檔案走鏡像加速。

一句話人話

號稱「下載器的集大成者」的開源下載器：一個 App 收下 HTTP、磁力／BT、FTP、M3U8、DASH、eD2k，YouTube 和 B 站還能選片段、選畫質、抓字幕。一天 +1,102 星、增幅 6.80%，總星 17,300——連漲第五天，五期抓榜新增合計 +4,726 星；今天它的絕對新增是全場第一，只是基數比 AutoClip 大，增幅以 0.05 個百分點之差排第二。

它到底是幹嘛的

協議全家福與命令列介面前幾期講過了，今天只講發稿前對照 README 剛核實過的三處「出身與邊界」。第一，出身寫在 About 裡：一開始是作者幫一位 B 站創作者管素材的興趣專案，現在出貨到四個平台、幾乎所有下載協議都接，外掛生態 Feature Packs 也在長——從「一個人的麻煩」長成「一群人的工具」，路徑寫得很坦白。第二，手機不是縮水版：Android 9.0+、arm64-v8a，README 明寫能在 Android 上錄製直播 M3U8 串流、背景繼續下載，還有下載完成通知——手機那一面是「錄＋下＋通知」整套，不是桌面版的遙控器。第三，鏡像加速是寫給抓大檔案的人的：功能清單裡，GitHub 與 Hugging Face 旁邊標的是「鏡像加速」——對常抓公開數據集、模型權重的人來說，這一句比協議多寡更實在。邊界也照舊寫在明處：平台表是 Windows 10+、macOS 13.0+、Linux glibc 2.35+、Android 9.0+；Qt 6.6+ 不再支援沒有 AVX 指令集的 CPU，舊機器裝之前先看這條警告；翻譯走 Crowdin，新語言要桌面文字翻到 60% 才收進 App，未翻的部分顯示英文；路線圖目前只剩兩件未勾選的事——把外掛 API 公開、以及加強任務編輯（例如把多個 Session 綁到同一個任務），不多畫餅。

它火在哪

一是「輸名次、贏絕對數」本身就是增幅榜的日常：+1,102 星是今天全場最多，但基數 16,198 星比 AutoClip 大，增幅就差那麼 0.05 個百分點——看增幅榜要同時看絕對數，不然會以為第二名漲得慢。二是連漲第五天沒有斷：+1,082、+774、+690、+1,078、+1,102，中間落榜一天也沒掉隊，說明裝的人不是看新聞來的，是用完回來推的。三是它講的場景越來越具體：手機錄直播、鏡像加速抓大檔案——這些都不是「下載很快」這種空話，是每天真的會遇到的兩件事：人在外面想錄直播、回家想抓一個幾 GB 的公開模型。

值得學什麼

最值得偷的是 「出身寫出來，信任就來了」：README 的 About 不講願景，講「幫一位創作者管素材」這個具體起點——工具的來歷越具體，讀者越敢信它真的解決過真問題。另一招是 「手機版也要有獨門本事」：Android 版不只是縮小版桌面，而是有「錄直播＋背景下載」這種手機才需要的招——跨平台不是每個平台長一樣，是每個平台都有自己非它不可的理由。還有 「路線圖越短越可信」：只剩兩件未完成的事，寫完就停——讀者一看就知道作者現在在忙什麼，不會被一張畫滿格子的路線圖嚇跑。

先說清楚邊界：這是個下載工具，能下載什麼、該不該下載，要看內容本身的授權與平台規則——只抓自己有權取得的內容，別拿它去繞過付費牆、抓盜版或侵犯著作權。它本身不是惡意程式、詐騙、色情或政治敏感內容，所以照常入選；但怎麼用，是使用者的責任。
我們怎麼用：常抓公開數據集、模型權重或工具站要用的公開大檔案的人，先看 README 裡 GitHub／Hugging Face 鏡像加速那條，再決定要不要把它接進流程；命令列流程照舊是 ghd probe 先預覽、ghd add --select 只抓要的檔案、ghd wait 等完再往下走。舊 CPU 的機器裝之前先對一下 AVX 那條警告，別裝完才發現跑不起來；Android 上只錄自己有權錄的直播。對工具站來說，今天最值得帶走的是那句「出身寫出來」：以後報告裡的新工具，先寫它原本是為誰、為哪件具體事做的，再寫它現在能幹嘛。
