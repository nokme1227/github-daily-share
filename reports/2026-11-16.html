SkillEvaluator：技能寫了一堆，誰來考考它們及不及格？NVIDIA 說：我來

NVIDIA / SkillEvaluator · Apache-2.0 協議 · Python · 2026 年 6 月建立 · 11-16 當天仍有更新進主線 · fork 358

插畫：考官的三層關卡——先靜態檢查，再查重疊、造考題，最後讓 agent 真跑一次，對照有沒有這個技能的差別。

一句話人話

給 AI agent 技能打分的考官：技能資料夾丟進去，它一層一層考——品質過不過關、有沒有跟別的技能重複、用上去 agent 是不是真的變強了。昨天 +205 還排第 4，今天 +953、增幅 55.76% 直接登頂，總星 2,662，基數只有 1,709——小專案，大增幅。

它到底是幹嘛的

Agent 技能就是一包指令加配套檔案（按 Agent Skills 規範寫的資料夾），現在人人都在寫技能，問題是：寫出來的技能到底好不好，沒人說得準。SkillEvaluator 就是 NVIDIA 做的評測框架，分三層考：第一層品質檢查是靜態的，不用 LLM 就能跑，範例技能拿了 88.8 / 100（B），及格線預設 70；第二層查語義重疊（兩個技能是不是在講同一件事），還會自動生成合成評測資料集；第三層真人實測，讓 agent 真跑任務，對照「有這個技能」和「沒這個技能」的結果差多少。進去有三條路：pip install skillevaluator 之後 skillevaluator validate ./my-skill --tiers 1 直接考；skillevaluator ci init 一把接進 GitHub CI，每次改技能自動開考；或是 npx skills add NVIDIA/SkillEvaluator 把它掛進 Claude Code、Codex，直接問 agent「我的技能好不好」。它是 NVIDIA Verified Skills 產線的一環，Apache-2.0 協議。

它火在哪

一是它踩在「Agent Skills 生態大爆發」的正中心：技能越寫越多，缺的不是寫技能的工具，是驗技能的工具——考官比考生稀缺。二是數字跳得夠戲劇：昨天 +205，今天 +953，一天翻了 4 倍多，說明昨天進來的人回去一試，覺得真有用，今天又帶了更多人。三是門檻想得很周到：第一層不用 API key、不用 GPU、不用 Docker 就能跑，範例五分鐘出成績單，願意試的人就多了。四是 NVIDIA 官方出品加 Apache-2.0，背書和授權都沒短板。

值得學什麼

最值得偷的是「有技能 vs 沒技能，對照跑一遍」這個思路：一個東西有沒有用，不能只看它自己跑得多漂亮，要看「有它」和「沒它」的差別——這才是評測，不是自誇。另一招也值得學：第一層先做確定性檢查，不花 token——格式、結構、重疊這種能算出來的，先算出來；要花模型錢的，留到後面再考。分層這件事本身，就是一種成本控制。

我們怎麼用：這期最對我們胃口的一名。我們的雙助手流程——研究、核實、裁決、結算——本身就是一套「技能」，到現在都是靠人工感覺在驗，從來沒有一個考官。先試第一層就好：pip install skillevaluator，skillevaluator validate ./my-skill --tiers 1，不用 API key，五分鐘就能看到一份確定性評分；把「流程寫成檔案」那套（見第三名）拿去給它考，就是現成的閉環：寫流程的人、考流程的人，分開。

PaperOrchestra：寫論文最苦的三件事，交給一支樂隊分工幹

google-research / paper-orchestra · Apache-2.0 協議 · Python · 2026 年 5 月建立 · 11-15 當天仍有更新進主線 · fork 236

插畫：點子跟實驗記錄是原料，五個 agent 是樂手，LaTeX 稿件是演出來的曲子——分工寫論文，就是這個意思。

一句話人話

Google Cloud AI Research 做的多 agent 論文寫作框架：把點子跟實驗記錄丟進去，一群專門的 agent 分工——列大綱、查文獻、寫各節、潤色、畫圖——最後交出一份能投稿的 LaTeX 稿件。一天 +306 星、增幅 26.27%，總星 1,471，基數 1,165。

它到底是幹嘛的

寫論文最苦的三件事：大綱不知道怎麼列、文獻不知道查全了沒、圖不知道怎麼畫。PaperOrchestra 的答案是把這三件事拆給五個 agent：Outline 列大綱、Literature Review 搜文獻並排優先級、Section Writing 寫各節、Content Refinement 潤色、Plotting 用程式把圖畫出來。文獻合成是自動的：搜、排、整合進正文一氣呵成；輸出是 LaTeX，會議模板放在 templates/ 底下（例如 CVPR 2025），想投哪個會就換哪個模板。裝法是 conda create -n paper_orchestra python=3.11、pip install -r requirements.txt，跑起來是 ./paper_writing_cli.sh，或直接 python paper_writing_cli.py --raw_materials_dir /你的材料/ --latex_template_dir /模板/ --output_dir /輸出/ --use_plotting true。有兩件事要先說清楚：模型要自備 API key（Gemini 或 OpenAI，文獻還要 Semantic Scholar 的 key），寫論文用的資料集不在倉庫裡，要另外下載；另外倉庫裡還有一個 Streamlit 互動 demo 可以先玩。

它火在哪

一是它戳中的是真痛點：每個寫過論文的人都知道，從實驗記錄到能投稿的稿子，中間那段路最磨人。二是「多 agent 分工寫長文」是當下最熱的範式之一，Google Research 出品，名字又取得好——PaperOrchestra，論文樂隊，聽一次就記住。三是數字結構乾淨：基數 1,165 還很小，+306 就是 26.27%，不是靠體量撐場面。

值得學什麼

最值得學的是「長文先拆工種，再排流水線」：大綱、文獻、寫作、潤色、畫圖各管一攤，一棒接一棒，而不是叫一個模型從頭寫到尾——長文寫崩，十次有九次是因為一個人幹了全部的活。另一招是「格式交給模板」：LaTeX 模板先定好，內容只管填進去，格式問題不進寫作流程，這招換到任何長報告上都管用。

我們怎麼用：對照我們的個股報告和裁決書流程想一想：研究、核實、裁決、結算四步，本質上也是一條 agent 流水線——差別只在我們現在是人手推進，它是寫成程式跑的。它的「大綱先行、文獻先查、最後才寫正文」這個順序，可以直接抄到長報告的寫作裡：先列大綱、再查數、再下筆，別一上來就寫正文。想動手試的話注意兩件事：要自備 Gemini 或 OpenAI 的 API key，資料集也不在倉庫裡，別空手去跑；先玩 Streamlit demo 看看流水線長什麼樣，再決定要不要接進來。

Claude Trading Skills：第三天，新增一天比一天多——先給自己用，跑順了再開源

tradermonty / claude-trading-skills · MIT 協議 · Python · 2025 年 10 月建立 · 11-16 當天仍有更新進主線 · fork 1,329 · 僅供研究、不是投資建議

插畫：三根柱子一根比一根高——第一天進來的人沒走，第二天、第三天又帶了新朋友。

一句話人話

給 Claude Code 的投資流程技能包，第三天還在榜上：一天 +841 星、增幅 15.42%，總星 6,294。三天的新增是 +556、+707、+841，一天比一天多。先說清楚：它不給明牌、不下單、不承諾賺錢——README 一開頭就把這三句話寫明白了，教的是「怎麼做投資功課的流程」。僅供研究、不是投資建議。

它到底是幹嘛的

基礎介紹見 11-14、11-15 兩期：五條工作流（15 分鐘每日盤檢、每週長期組合檢視、只在風險允許時找波段機會、每筆平倉交易留記錄、每月績效檢討），每條都有一份機器可讀的 YAML 清單。今天只補三個新看點：第一，作者的立場寫在 README 最前面：first for self, open for others——先給自己用的流程，跑順了才開源，不是為了開源而寫。第二，邊界文件很齊全：隱私政策（docs/en/privacy.md）和安全政策（SECURITY.md）都單獨成文，範例輸出一律用虛構數據，還明確標示「不是即時行情、不是交易指令」。第三，付費依賴分級寫得一清二楚：每日盤檢的基礎路徑不用任何付費 API，長期組合檢視要 Alpaca，波段篩選要 FMP——要不要花錢，進門前就知道。文件站、Your First Week 新手路徑、日文版 README 也都齊了。

它火在哪

一是「三天連漲、新增遞增」本身就很罕見：日榜是個喜新厭舊的地方，同一張臉連著三天站前三，而且一天比一天多，說明第一天進來的人沒走，還在拉人。二是它反其道而行：別的投資工具都在比「訊號多準」，它一開頭就說「我不給訊號」——在滿是明牌的圈子裡，「不給明牌」本身就是一種信任狀。三是 fork 數 1,329，動手拿回去用的人不少，不是只來看熱鬧的。

值得學什麼

前兩天講了「流程比判斷值錢」和「流程要寫成機器可讀的檔案」，今天補第三招：「先給自己用，跑順了再開源。」工具先過自己這一關，別人拿去才不會踩坑——這句話換到我們的工具站上也一樣：新功能先自己查、自己用，跑順了再上線。另一招是「範例數據一律虛構並標示」：演示跟實盤的界線寫在明面上，讀者不會把示意圖當成行情看。

我們怎麼用：先潑一盆冷水：別拿它來選股下單，更別拿計劃資金實盤——先模擬盤走一段時間，流程跑順了再說。值得偷的是它的立場：「先給自己用」——我們的工具站、辯論流程也是先自己跑順再說，這條路是對的；另外它的「範例數據虛構」做法可以直接學：我們的回測示意、範例圖表，也該把「示意」兩個字寫在明面上，別讓人誤會是實盤。僅供研究、不是投資建議——這句話，作者寫在 README 裡，咱們也原樣貼在這裡。
