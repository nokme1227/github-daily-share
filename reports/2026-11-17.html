PaperOrchestra：昨天 +306，今天 +1,175——樂隊昨天只是試音，今天才正式開演

google-research / paper-orchestra · Apache-2.0 協議 · Python · 2026 年 5 月建立 · 11-15 當天仍有更新進主線 · fork 411

插畫：昨天那根柱子只是試音，今天這根才是正式演出——同一支樂隊，觀眾一天翻了四倍。

一句話人話

Google Cloud AI Research 的多 agent 論文寫作框架，昨天第二、今天第一：一天 +1,175 星、增幅 66.09%，總星從 1,471 翻倍到 2,953。基礎介紹見上一期，今天只補三個新看點：它連自己的產出都拿機器來評分、它有正式的 arXiv 論文背書、以及一句老實到有點意外的免責聲明。

它到底是幹嘛的

基礎介紹見 11-16 期：五個 agent 分工（大綱、文獻、寫作、潤色、畫圖），把點子跟實驗記錄寫成能投稿的 LaTeX 稿件。今天補三個上一期沒寫的細節。第一，倉庫裡有一個 autoraters/ 目錄，放的是自動評分腳本——這支樂隊不只寫論文，還自己給寫出來的東西打分，等於內建了一個小考官，跟昨天第一名的 SkillEvaluator 是同一種思路，只是它評的是論文不是技能。第二，作者是 Google Cloud AI Research 的四個人（Yiwen Song、Yale Song、Tomas Pfister、Jinsung Yoon），有正式的 arXiv 預印本（arXiv:2604.05018），不是隨手丟出來的 side project。第三，README 最底下有一行免責聲明寫得很白：「這不是 Google 官方支援的產品」——Google Research 出品沒錯，但官方不背書，用之前先知道這件事，出了問題別去找客服。

它火在哪

一是數字本身夠戲劇：昨天的 +306 已經是第二，今天的 +1,175 是昨天的 3.8 倍，總星一天翻倍——這種「第二天比第一天更兇」的走勢，日榜上很少見，說明昨天進來的人回去一試，覺得真能寫，今天又帶了更多人。二是它踩在兩個熱點的交叉口：多 agent 分工寫長文是當下最熱的範式，而「寫論文」是每個研究者都有的真痛點，兩邊的人都進來了。三是它有論文背書：arXiv 預印本一掛，可信度立刻不一樣，讀者不用只憑 README 判斷它行不行。

值得學什麼

最值得偷的是 「產出物要自帶評分器」：寫完論文，同一套倉庫裡的自動評分腳本立刻打分——產出跟評分長在同一個地方，品質才不會只靠感覺。這招換到任何地方都管用：報告寫完先跑一遍確定性檢查，再交給人或模型審，順序不能反。另一招是 「免責聲明寫在明面上」：不是官方支援的產品就老實寫出來，讀者自己判斷要不要賭——這種老實，反而比含糊的背書更讓人放心。

我們怎麼用：對照我們的雙助手流程想一想：研究、核實、裁決、結算四步，現在是人手推進，品質靠終審把關。PaperOrchestra 的 autoraters/ 給了一個現成的樣子——把「檢查清單」寫成腳本，先讓機器跑一遍確定性的分，再交給人審；我們的 P1 自查、六大指標計分，都可以往這個方向想：能算的先算，人只審算不出來的部分。想動手試的話還是那兩句話：要自備 Gemini 或 OpenAI 的 API key，寫論文用的資料集不在倉庫裡，別空手去跑；先玩 Streamlit demo 看看流水線長什麼樣，再決定要不要接進來。

LoopForge：隔了一天回來，新增比上次還多——這次補上「不想架伺服器」的那條路

Tencent / LoopForge · MIT 協議（README 標示）· Go · 自架工作室 · 2026 年 7 月建立 · 11-17 當天仍有更新進主線 · fork 436

插畫：平台版是整間工作室，Local 版是把工作流程直接帶進你手邊的工具——同一套 SOP，兩種出場方式。

一句話人話

騰訊的自架工作室回榜了：11-15 期第一（+484），隔一天回來又 +590 星、增幅 23.47%，兩天合計 +1,074，總星從 1,457 漲到 3,104，直接翻倍還多。基礎介紹見 11-15 期，今天只補一個上一期沒寫的重點：不想架伺服器的人，現在有另一條路。

它到底是幹嘛的

基礎介紹見 11-15 期：Main Bot 聊天交件、SOP 照表操課、Human-gate 人工把關、十種 coding agent CLI 當執行器。今天補的是 LoopForge Local：不想跑伺服器，就把內建的工作流程直接帶進你本來就在用的 coding assistant 裡跑，例如 Claude Code，原始碼在倉庫的 local/ 目錄。兩條路的差別寫得很老實：平台版有網頁工作室、共用的審批紀錄和指標，Local 版的證據留在本機 artifacts/{task_slug}/ 底下，外加一個可選的本地儀表板；把平台上的 SOP 匯出來給 Local 單獨跑，目前還是「計畫中」，還沒做。另一個上一期沒寫的小細節：接 GitHub 不用自己填 PAT，走 device code 授權就行，內建的 OAuth App 已經配好了。

它火在哪

一是「回榜第二天比第一天更兇」本身就是訊號：11-15 期 +484，隔一天 +590，總星兩天翻倍——第一天進來的人沒走，還在拉人，說明不是一日遊。二是 Local 版把門檻砍了一大截：上一期最大的勸退點就是「要架伺服器」，現在不用架也能先試流程，先用順了再決定要不要上平台版。三是它的定位剛好卡在兩個熱潮中間：coding agent 人人都在用，但「怎麼讓 agent 照流程交件、還要人點頭」一直沒個現成答案，騰訊直接把答案開源了。

值得學什麼

最值得偷的是 「同一套流程，兩種出場方式」：平台版給團隊、Local 版給個人，SOP 寫一次，兩邊都能跑——這就是把「流程」跟「載體」分開，流程是資產，載體只是出場方式。另一招是 「沒做的事寫『計畫中』，不裝作已經有了」：SOP 匯出給 Local 跑還沒做，README 就寫計畫中，讀者不會白跑一趟。這種老實，上一期在 PaperOrchestra 的免責聲明也看到了，好的開源專案都這樣。

我們怎麼用：上一期說先跑內建 demo SOP 看 Human-gate 長什麼樣，今天補一句：不想架伺服器的話，先試 Local 版——不用起 MySQL、不用開 8090 埠，流程直接跑進你本來就在用的助手裡，證據留在本機 artifacts/ 底下。對照我們的雙助手流程想一想：研究、核實、裁決、結算四步，現在是人手推進，Local 版給了一個「先在本機把流程跑順、再決定要不要上平台」的台階，這個台階本身就值得抄。提醒一句：平台 SOP 匯出給 Local 還是計畫中，別現在就去找這個功能。

AG-UI：agent 跟前端各說各話的日子，該有個通用翻譯了

ag-ui-protocol / ag-ui · MIT 協議 · TypeScript · 2025 年 5 月建立 · 11-17 當天仍有更新進主線 · fork 2,067

插畫：agent 那頭只管發事件，前端這頭只管照事件畫畫——中間那條流一統江湖，框架換了也不用重寫前端。

一句話人話

一份開放協議，專門解決「agent 跟前端各說各話」的問題：agent 一邊串流 token、一邊調工具、一邊改共享狀態、還要中途停下來等人點頭——每個框架的做法都不一樣，前端只好一個一個接。AG-UI 的答案是：一條雙向事件流，agent 只發帶型別的事件，任何前端照著渲染就行，換框架不用重寫前端。一天 +1,444 星、增幅 7.79%，總星 19,981，基數 18,537——這期主榜裡體量最大的一個。

它到底是幹嘛的

核心就一句話：agent 不適合 request/response 那套，它會串流、會調工具、會暫停等人、會生子 agent，所以 AG-UI 用事件流取而代之——agent 發事件，前端接事件，同一個 agent 可以同時餵網頁、手機、終端機、Slack。1.0 版是這期的重點：規格已經凍結，有 JSON Schema 背書，TypeScript、Python、.NET 三個 SDK 都是由規格自動生成的，0.x 跟 1.0 雙向相容，舊的 agent 接新的前端、新的 agent 接舊的前端都行。裝起來有兩條路：想快速開一個前端，npx create-ag-ui-app@latest 會搭好一個接好 agent 框架的架子（模板會調 OpenAI，跑之前先設 OPENAI_API_KEY）；想直接摸協議本身，README 給了一個 30 行的 Python 範例——pip install ag-ui-protocol fastapi uvicorn，寫一個回傳事件流的 endpoint，uvicorn server:app --port 8000 就跑起來了，不用 API key。支援的框架一長串：LangChain、CrewAI、Mastra、Google ADK、微軟 Agent Framework、Pydantic AI；功能清單也齊：串流對話、生成式 UI、共享狀態、 human-in-the-loop、前端工具、子 agent。定位也寫得很清楚：它跟 MCP、A2A 不是競爭關係——MCP 管工具、A2A 管 agent 之間對話，AG-UI 管 agent 跟使用者介面之間。

它火在哪

一是 1.0 凍結版規格這個時間點：協議這種東西，沒凍結之前大家不敢重押，一凍結、SDK 又是自動生成的，觀望的人就進場了。二是它解決的是真痛點：每個做 agent 應用的團隊都寫過同一段膠水程式碼——把 agent 的輸出翻譯成前端能畫的東西，AG-UI 就是把這段膠水變成標準。三是體量跟漲勢對得上：總星快兩萬、fork 2,067，動手拿回去接的人不少，不是只來看熱鬧的；昨天 +1,444 星是全場絕對新增第二，增幅 7.79% 也穩穩過了 5% 門檻。

值得學什麼

最值得偷的是 「規格先凍結，SDK 由規格生成」：先把協議寫死、寫成 JSON Schema，再讓機器去生三種語言的 SDK——人只維護一份規格，程式碼不會三邊各寫各的、慢慢走樣。這招換到任何地方都管用：我們的資料格式（行情庫、JSON 分片）也該有一份「規格」當源頭，程式去讀規格，而不是各寫一份、事後再對。另一招是 「定位寫清楚，不搶別人的活」：MCP 管工具、A2A 管 agent 對話、AG-UI 管 agent 跟介面——三句話講完自己的邊界，別人一看就知道該不該用你。

我們怎麼用：我們的工具站現在是純靜態頁面，還沒有 agent 藏在後面，所以今天先不用急著裝它。但有兩樣東西可以直接學：第一，「規格當源頭」——我們工具站的 JSON 分片格式、行情庫欄位，值得寫一份凍結版規格當源頭，免得以後各寫一份再慢慢對不上；第二，human-in-the-loop 那個事件——agent 跑到一半停下來等人點頭，這個模式跟我們的雙助手流程（核實、裁決要人拍板）是同一件事，將來如果工具站要接一個「問問這個專案」的對話框，AG-UI 就是現成的接線方式。想動手的話，先跑那個 30 行 Python 範例，不用 API key，五分鐘就能看到事件流長什麼樣。
