auto-ontology：AI 查數查得快沒用，查得對、還能交代出處才算數

NVIDIA / auto-ontology · Apache-2.0 · Python（後端）＋ Next.js 前端 · 昨日基數 2,845 星

插畫：auto-ontology 的流程不是「問了就答」，而是「先認詞、再寫 SQL、最後把 SQL 和步驟一起交出來」。

一句話人話

給 AI 先發一本「名詞解釋＋算法手冊」，而且是經過人認證的那本，之後它每次查數，都得照著手冊來、還得把算式交出來給你驗。

它到底是幹嘛的

這是 NVIDIA 做的一個 Python 框架，幫資料建一層「語意圖譜」：從企業資料庫的中繼資料（metadata）長出本體（ontology），把不同系統裡對同一個詞的不同說法調和成同一套定義，再透過 MCP、CLI 和 API 交給任何 agent harness 用。它的本體裡有三種東西：詞彙（例如「客戶」「發票明細」，含描述、同義詞、對應欄位）、SQL 屬性（事先審過的 SQL 運算式，例如某個利潤或滾動合計，agent 直接複用，不必每次重寫）、關係（表跟表怎麼 join，含橋接表，從鍵和資料推斷）。流程分三段：生成（從來源資料庫抽 schema、探查欄位、抽詞、推關係，寫進 Postgres＋pgvector）、認證（人在介面或 API 裡修詞彙、描述和 SQL 屬性，確認無誤才算認證）、回答（agent 先分類意圖、抽實體，用向量檢索找候選詞彙和屬性，寫 SQL、對照資料庫驗證過濾值、修不好就直說答不出來，最後把答案連同 SQL 和步驟一起回傳）。元件表 README 寫得很直白：前端 Next.js、後端 FastAPI、 ingestion worker 也是 FastAPI、Postgres＋pgvector 存目錄與本體，Vault 可選，部署可用 Helm 上 Kubernetes 或 Docker Compose 起本地堆疊。推理預設走 NVIDIA NIM 端點，需要一把 NVIDIA API key。

它火在哪

第一，數字是真的陡：昨日基數只有 2,845 星，一天 +2,053 星，增幅 72.16%，是今天增幅榜的斷層第一，也是絕對榜第二。第二，它打中的痛點很具體：README 開頭就說，agent 查資料時「答得快但數字錯了，等於白答」——可靠性才是 agentic analytics 的門檻。第三，它不是只有概念：Quickstart 寫到能直接跑，git clone https://github.com/NVIDIA/auto-ontology.git、cp .env.example .env 填好 key，再 docker compose up -d --wait postgres、docker compose up -d --build，打開 http://localhost:3000 就能用範例資料庫問問題；文件、MCP 伺服器、agent skills、REST API 也都齊全，提交頁上也還在合併（目前最新提交是 #413），不是丟上來就跑的演示。

值得學什麼

「定義先認證」比「模型再換大一點」更能止錯。很多查數翻車不是模型笨，而是兩個來源對同一個詞的算法本來就不一樣——模型再強，也只能在兩種正確答案裡猜一個。auto-ontology 的解法是把「哪個定義算數」變成一個需要人點頭的認證動作，之後所有查詢都複用同一條 SQL 屬性，錯了也知道去改哪一條。另一件值得偷的是「答案附算式」：它回傳的不只是數字，還有 SQL 和推導步驟，數字能不能信，看一眼算式就知道，不必再追問一次。

我們怎麼用：先說清楚：不建議把整套企業堆疊直接搬上工具站——要 Docker、Postgres，還要 NVIDIA API key，對一個靜態工具站來說太重了。但三個做法可以直接偷：第一，給工具站建一本小小的「指標字典」，每個指標寫死定義、來源和計算式，入庫前先對字典，不合的先擋下來別硬入；第二，同一指標只留一種算法，別讓兩個頁面各自算一次；第三，報告裡的關鍵數字盡量附上可核查的算式或來源，不只給結論。真想動手試，也只在測試環境用 README 的範例資料庫（Wide World Importers）跑一圈就好，別接真實資料。

DiscImageStudio：把圖刻進光碟的數據裡，盤面自己就是一幅畫

JiaFeiMiao-K-Cat / DiscImageStudio · GPL-3.0 · C# · Windows 桌面版＋ Linux／macOS 實驗性 CLI · 昨日基數 4,776 星

插畫：DiscImageStudio 不是在盤面上貼紙，而是讓寫入的數據本身排成圖案，檔案功能還在。

一句話人話

你給它一張圖，它算出一組符合光碟物理規則的數據，刻完之後，盤面肉眼看得到這張圖——而且這張盤還能照常存檔案。

它到底是幹嘛的

這是一個多平台的光碟盤面可見圖像生成與刻錄工具：用任何刻錄光驅，在任何 CD、DVD 或單層藍光（BD-R 25GB）上刻出肉眼可見的圖案。流程是三步：主頁選 CD、DVD 或藍光、指定輸出位置建工程；設計頁匯入圖片、用圖層排版，在右欄「影調」模組調抖動、伽馬、亮度和灰階檔位；預覽頁核對盤面投影，匯出頁生成 ISO／RAW／WAV＋CUE，或用即時刻錄直接寫入空白盤片。功能表很實在：CD 支援帶格式頭的 WAV 音軌加配套 CUE（也支援 RAW 音軌），DVD 匯出 ISO，藍光支援純繪圖與 UDF 2.01 檔案；設計頁就能選隨盤檔案夾和內圈／外圈位置，檔案區在設計投影和成品讀回裡用黃色標出；還有粗標定、邊界標定、精細標定三段流程，靠盤面照片估計內外半徑與軌距分布，修正後徑向線條更接近直線。安裝也直接：Windows 下載 win-x64.exe 就能跑（自帶 .NET 執行環境），Linux 或 macOS 下載對應 CPU 的實驗性 CLI 壓縮包，解壓後跑 ./disc-image-studio --help；CLI 範例 README 有寫：./disc-image-studio cd-generate --input picture.png --output sample.wav --sectors 2。從源碼建置則是 dotnet build DiscImageStudio.slnx --configuration Release。

它火在哪

第一，數字不摻水：昨日基數 4,776 星，一天 +1,792 星，增幅 37.52%，絕對榜第三；專案 2026-08-23 才建立，至今 72 次提交、10 個版本，昨日也有提交，不是曇花一現的梗圖專案。第二，它把一件「聽起來像魔術」的事寫成了工程手冊：參考標準對照表（CD-R、DVD、BD-R 各引 ECMA／ISO 規範與採用範圍）、物理模型複核文件、標定實操教程一應俱全，連「實測精度取決於照片矯正、取點和複刻驗證，參數小數位數不代表測量精度」這種老實話都寫在前面。第三，安全須知先講在前面：即時刻錄是實驗性功能，只用可報廢的測試介質、拒絕非空白介質、不裝驅動或服務（用 Windows 自帶 IMAPI2），而且專案本身不聯網、不上傳檔案、不收集遙測。

值得學什麼

把限制寫成規格，限制就變成了設計材料。一般人看到光碟的物理層約束，第一反應是「這不能幹嘛」；這個專案是反過來問：「在這些約束裡，數據排成什麼樣子，盤面看起來就是什麼圖案？」約束一旦被精確描述，就從絆腳石變成了畫布。另一個值得偷的是標定方法論：先粗標、再邊界、再精細，用實拍照片回頭修正模型參數——這種「模型→實測→修正模型」的迴圈，換到任何需要把理論對上現實的流程都管用。

我們怎麼用：老實說，對工具站來說它沒有直接用途——沒有刻盤需求就不用裝，別為了追星而裝一個用不上的工具。真正要偷的是上面兩件事：第一，數據管線先寫約束再跑，例如某個指標的基期門檻、某個欄位的合理範圍，先寫成規則擋在入庫前面，而不是跑完看到異常再回頭解釋；第二，任何「理論值 vs 實測值」對不上的地方，都照標定流程走：先量、再修正參數、再驗一次，別憑感覺調參數。如果真的有懷舊刻盤或實體備份的需求，先用匯出 ISO／WAV＋CUE、再用熟悉的刻錄軟體刻；即時刻錄只拿可報廢的測試盤試，正式盤別拿來練手。

agent-desktop：連莊第三天，漲勢放緩了，但絕對新增還是全場第一

vercel-labs / agent-desktop · Apache-2.0 · Rust · macOS、Windows、Linux 皆可用 · 昨日基數 12,554 星

插畫：agent-desktop 三天增幅曲線：衝高、再衝高、然後回落——但回落那天的絕對新增仍是第一。

一句話人話

前兩期講過的桌面操作工具，今天第三次上榜：核心沒變，變的是曲線——從暴衝變成穩步走，還是過門檻、還是全場新增最多。

它到底是幹嘛的

幫昨天、前天沒看的人補一句：這是給 AI agent 用的電腦操作 CLI 與 C 函式庫，支援 macOS、Windows 和 Linux。它讀作業系統的無障礙樹、回傳 JSON，每個可操作元件都有編號（ref），agent 照編號行動、再快照驗證，全程不用截圖猜像素；而且 README 明寫：它裡面沒有模型，迴圈留在你的 agent 手裡。安裝是 npm install -g agent-desktop，macOS、Linux 上也能 brew install agent-desktop；前一期補上的 MCP 模式是 agent-desktop mcp，會把每個命令變成 MCP 工具（例如 desktop_snapshot、desktop_click），任何支援 MCP 的 agent 都能直接叫它操作桌面。今天這一期沒有要再展開講一次命令表——前兩期已經講過快照、按編號行動、再快照驗證的迴圈，今天的重點是數字本身。

它火在哪

第一，連莊本身就是消息：11-02 榜單 +2,243 星、增幅 30.63%，11-03 榜單 +3,792 星、增幅 42.74%，今天 +2,463 星、增幅 19.62%——三天主榜全勤，總星從 9,567 衝到 15,017。第二，增幅放緩要老實解讀：分母（昨日基數）從 8,872 漲到 12,554，基數變大後同樣兩千多星的增幅自然變小；但看絕對數，今天 +2,463 星仍是日榜第一，比第二名還多 410 星。第三，維護沒停：昨日提交仍在推進，fork 數已到 1,038，文件與 MCP 接法都是現成的，不是漲完就丟著的專案。

值得學什麼

看漲勢要兩個數一起看，單看增幅會誤判。增幅是「相對於昨天體量」的速度，絕對新增是「今天到底有多少人新加入」——體量一大，增幅一定會自然回落，這時候只看增幅會以為它涼了，只看絕對數又會忽略它其實在放緩。兩個數一起看才完整：agent-desktop 今天就是「放緩、但仍是第一」的狀態，既不是第二春，也不是退潮。這個讀法換到任何榜單、任何指標都一樣：分子、分母、基數，三個一起講，才不至於自己騙自己。

我們怎麼用：前兩期的試法和紅線今天照舊，不再重複展開：先在不放敏感資料的測試機上試，熟悉「快照 → 按編號 → 再快照」的手感；對工具站來說，真正要偷的還是那個驗證迴圈——以後寫自動檢查流程時，照著「每步行動後必須再看一次、證據過期就重抓」來設計。兩個紅線跟前兩期一樣：README 明說快照、剪貼簿、截圖與命令輸出可能含私人桌面內容，絕對不要貼進公開日誌或上傳；也不要拿它去點交易軟體、做任何會動到真金白銀的操作——這期只是研究一個工具，不是叫你把它接上實盤。已經裝過的人，今天沒有非跟不可的新理由，不必為了連莊而重裝一次。
