agent-desktop：給 AI 一張桌面的「結構圖」，而不是一張截圖

vercel-labs / agent-desktop · Apache-2.0 · Rust · macOS、Windows、Linux 皆可用 · 321 次提交、47 個版本、646 個 fork

插畫：agent-desktop 的核心迴圈——快照、按編號行動、再快照驗證，錯了就重抓，不硬猜。

一句話人話

以前讓 AI 操作電腦，像是叫一個人矇著眼睛看截圖猜按鈕在哪；agent-desktop 是直接把桌面的「結構圖」交給 AI：視窗裡有什麼、每個東西叫什麼、能不能點，全寫成 JSON，還附上編號，AI 照編號辦事就行。

它到底是幹嘛的

按 README 的說法，這是一個給 AI agent 用的電腦操作 CLI 與 C 函式庫，支援 macOS、Windows 和 Linux。一次快照會回傳 JSON，裡面每個 agent 能操作的元件都有一個 ref（編號）；agent 照著 ref 行動，再快照一次檢查，全程不用像素比對，迴圈留在 agent 自己手裡。安裝命令 README 寫得很直接：npm install -g agent-desktop，再跑 agent-desktop version 確認；macOS 需要無障礙權限（agent-desktop permissions --guide），Linux 需要圖形 session 與 at-spi2-core。上手的三步也是 README 的範例：agent-desktop snapshot --app Finder -i 看互動元件、agent-desktop click @s8f3k2p9:e8 按編號點、再 snapshot 一次驗證。命令總共有 60 個名字、56 個可實際操作的命令，分觀察、按編號行動、鍵盤滑鼠、應用與視窗、通知、剪貼簿、等待、 session 與系統幾組；文件也齊全，連二進位自帶的技能說明（agent-desktop skills get desktop、skills get platform）都寫在 README 裡。

它火在哪

第一，數字夠硬：昨日基數只有 7,324 星，一天就多了 2,243 星，增幅 30.63%，是今天唯一同時過「新增 ≥300、增幅 ≥10%、基數 ≥1000」三關的專案——不是大專案例行漲一點，是小基數真的起勢了。第二，痛點夠真：用截圖加座標操作桌面的做法，換個解析度、換個視窗大小就容易點歪；讀無障礙樹等於讀結構，穩定得多。第三，工程細節夠老實：README 明寫預設是無頭模式，ref 行動走無障礙 API，不動滑鼠指針、不搶焦點；編號只屬於當次快照，裸寫 @e8 會被拒絕，介面變了就回傳 STALE_REF 或 AMBIGUOUS_TARGET，叫你重抓快照——與其讓 AI 硬猜，不如讓它承認「這張圖過期了」。最近一頁提交也多半是文件整理與 1.0.2 版本準備，看得出是個還在認真維護的專案，不是丟上來就跑的演示。

值得學什麼

「能驗證的迴圈」比「一次到位的聰明」值錢。這個專案最值得偷的不是命令表，而是它的流程設計：每一步行動之後都必須再看一次，用新的快照確認結果；編號過期不硬撐，明確報錯、重新抓取。我們的報告複核流程也是一樣的道理——與其相信模型一次說對，不如規定「每一步都要有可再查的證據」，錯了就回到上一步重查，而不是往下硬編。另一個值得學的點是「把限制寫在前面」：預設無頭、拒絕裸編號、快照可能含私人桌面內容要遠離公開日誌——限制先講清楚，用的人反而敢用。

我們怎麼用：先在不放敏感資料的測試機上試，別一上來就裝在主力工作機：npm install -g agent-desktop 裝好後，先對一個無關緊要的應用跑 snapshot，熟悉「快照 → 按編號 → 再快照」的手感。對工具站來說，它真正的參考價值是驗證迴圈本身——以後寫自動檢查流程時，照著「每步行動後必須再看一次、證據過期就重抓」來設計，比單次截圖比對穩得多。兩個紅線要先記住：README 明說快照、剪貼簿、截圖與命令輸出可能含私人桌面內容，絕對不要貼進公開日誌或上傳；也不要拿它去點交易軟體、做任何會動到真金白銀的操作——這期只是研究一個工具，不是叫你把它接上實盤。
