auto-ontology：第三天還是它——增幅腰斬了，每天新來的人卻沒少

NVIDIA / auto-ontology · Apache-2.0 · Python（後端）＋ Next.js 前端 · 昨日基數 6,979 星

插畫：auto-ontology 三天對比——增幅數字一路縮水，是因為分母長大了；每天新來的人一直兩千上下，這才是它還在漲的證據。

一句話人話

前兩天講過的「AI 查數之前先認證定義」那套，第三天還是榜上第一：數字變的是增幅，不變的是每天都有兩千人新加入。

它到底是幹嘛的

完整介紹見 11-04、11-05 兩期，這裡只給新讀者一句話：這是 NVIDIA 的 Python 框架，幫企業資料建一層「語意圖譜」——詞彙、事先審過的 SQL 屬性、表間關係三種定義先由人認證，之後 agent 每次查數都照著同一套定義寫 SQL、附算式交出來，答不出就直說。部署是 Docker Compose 或 Helm 上 Kubernetes，推理走 NVIDIA NIM 端點，需要一把 NVIDIA API key；Quickstart 是 git clone https://github.com/NVIDIA/auto-ontology.git、cp .env.example .env、docker compose up -d --build，打開 http://localhost:3000 就能用範例資料庫問問題。

它火在哪

第一，三天連莊，而且是斷層式連莊：三天絕對新增分別是 +2,053、+2,707、+2,005，總星從 4,898 衝到 8,984，三天漲了 83%。增幅從 72.16% 回落到 28.73%，純粹是分母變大的數學，不是人跑了——每天新加入的人數一直穩定在兩千上下。第二，fork 也在跟著漲：昨天 574 個，今天 723 個，一天多了 149 個 fork，說明不只來看熱鬧的人多，動手拿去用的人也在變多。第三，維護沒停：提交數 1,366 次 → 1,367 次，專案頁顯示最後推送是 2026-11-06，不是漲完就丟著的專案。今天絕對新增它是全場第二（+2,005），只輸給 Cloudflare 的安全審計技能包（+2,524），但那個基數六萬多，增幅只有 4.11%，進不了增幅主榜。

值得學什麼

判斷一個專案是真火還是曇花，看絕對新增穩不穩，比看增幅準。增幅是個會自己縮水的數字——分母每天都在長，增幅遲早要回落；但每天新加入的人數如果一直維持在同一個量級，說明需求是真的在、不是一日遊。這個專案三天就是最好的教材：增幅腰斬再腰斬，每天新來的人還是兩千個。另一個值得偷的還是前兩天講過的：「定義先認證、答案附算式」，以及 README 裡那套「教 agent 用我」的 skills 寫法——一個好工具現在連說明書都一起打包了。

我們怎麼用：前兩天的三條偷法今天照舊：給工具站建一本小小的「指標字典」、同一指標只留一種算法、關鍵數字附上可核查的算式或來源。今天多補一條：把它當「復甦成長」邏輯的活教材——連續多日絕對新增穩定、fork 跟著漲，比單日增幅更像「趨勢確認」；我們自己的篩選也可以多看「連續幾天都在漲」而不是「今天漲最多」。整套堆疊要 Docker、Postgres 還要 NVIDIA API key，別直接搬上工具站；真想試，只在測試環境用範例資料庫跑一圈就好。

🔥 慢火榜 · 本週 +1,802 ⭐ · 週增幅 18.02% · 新面孔

worktrunk：git worktree 終於有了像 branch 一樣順手的操作

max-sixty / worktrunk · MIT 或 Apache-2.0（README 徽章） · Rust · 總星 11,799（本週前基數 9,997）

插畫：worktrunk 的用法就是一張圖——主倉庫分出幾個工作區，每個區一個 agent，幹完活一條命令合併清場。

一句話人話

一個讓 git worktree 好用到像 branch 的命令列工具：開新工作區、順手把 Claude 叫進去幹活、收尾合併清場，全部三個命令搞定，專門為「同時開好幾個 AI 助手」設計。

它到底是幹嘛的

背景先講一句：AI 助手現在能自己幹長任務了，同時開 5 到 10 個並行很常見；git 原生的 worktree 功能正好給每個助手一個獨立工作目錄，互不踩腳，但原生用法很彆扭——開一個工作區要把分支名打三遍。worktrunk 就是來治這個彆扭的 Rust CLI。核心就三個命令：wt switch feat 切換工作區，wt switch -c -x claude feat 建分支＋開工作區＋直接叫起 Claude，wt remove 清場；wt list 一眼看清所有工作區的狀態、CI 和 AI 寫的摘要。進階功能也很實在：hooks（建好工作區自動裝依賴、起開發伺服器）、共用 build cache（十個工作區共用同一份 target/、node_modules/，不用重複編譯拷貝）、LLM 生成提交訊息、一條命令合併（wt merge main：壓縮、rebase、合併、清場全包）。安裝是 brew install worktrunk && wt config shell install（macOS／Linux），或 cargo install worktrunk && wt config shell install；完整文件在 worktrunk.dev。5,508 次提交、153 個版本，昨日仍有提交，README 自己說它是「最受歡迎的 git worktree 管理器」。

它火在哪

第一，數字是整週燒出來的，不是單日爆發：本週 +1,802 星，週增幅 18.02%，基數 9,997——這種體量的專案一週漲近兩成，靠的是持續有人用、持續有人推。第二，踩在正熱的點上：同時開多個 AI 助手幹活，已經是這兩個月榜單上的常客題材（從 agent-desktop 到 OpenBot 都在講同一件事），worktrunk 補的是這條鏈上最底層的那一環——工作區管理。第三，維護證據很硬：2025-10-17 建立，一年時間 5,508 次提交、153 個版本，平均兩三天就有動靜，作者還在 README 裡寫「請告訴我任何一點摩擦」，這種一直在修的專案，漲勢通常不是曇花。

值得學什麼

把原生功能裡最彆扭的那一步包掉，就是一個好工具。git worktree 本身不缺功能，缺的是順手——worktrunk 沒有發明新東西，只是把「開區、叫 agent、合併、清場」四件事串成三個命令，痛點就解決了。另一個值得偷的是 共用 build cache：多工作區最痛的不是開區，是每個區都要重裝依賴、重編譯，它用 copy-on-write 讓十個區共用一份編譯結果，這種「把重複成本先算清楚再動手」的思路，跟我們做數據管線先寫約束再跑，是同一種手藝。

我們怎麼用：工具站正好是 worktree 的場景：靜態站＋多個排程並行改代碼，不同任務開不同分支、各跑各的工作區，互不踩腳——例如一邊改行情管線、一邊調工具頁面，不用來回切分支等對方。命令照抄 README 就行：wt switch -x claude -c feature-a -- 'Add user authentication' 一步開工區＋叫 agent。先在家目錄的測試倉庫試熟了，再用到工具站主倉庫；Windows 上 wt 會跟系統終端命令撞名，README 寫了用 git-wt 迴避，別硬搶。

怎麼裝起來試：macOS／Linux 裝 Homebrew 版：brew install worktrunk && wt config shell install；有 Rust 工具鏈就 cargo install worktrunk && wt config shell install；裝完先跑 wt --help 看一眼核心命令，再拿測試倉庫開第一個工作區。

🔥 慢火榜 · 本週 +2,085 ⭐ · 週增幅 52.59% · 黑馬回歸

OpenBot：十天前還是黑馬，今天回來時星數漲了 2.5 倍

nightly-labs / openbot · PolyForm Noncommercial 1.0.0（非自由軟體） · TypeScript · 總星 6,050（本週前基數 3,965）

插畫：OpenBot 從黑馬到慢火——十天前單日漲 49% 只能算「勢頭待觀察」，十天後星數 2.5 倍，這才叫燒起來了。

一句話人話

十天前它還是單日漲 49% 的黑馬，今天回來時星數已經 2.5 倍：給 Codex、Claude、Grok 這些 AI 隊友一人配一個工位，在同一台電腦裡上班，還能互相傳消息、排隊領任務。

它到底是幹嘛的

一個本地優先的桌面工作台，給每個 AI 隊友配獨立的工作區和對話，支援 Codex、Claude、Grok、OpenCode、Gemini、Cursor、Cline、Kimi、Devin、GitHub Copilot、Hermes，帶任務佇列、檔案傳輸、內置瀏覽器和隊友之間的消息往來；還能接本地模型伺服器（Ollama、LM Studio）。README 寫明它現在「已可投入生產使用」，「幾乎每天發新版」——2,973 次提交、117 個版本、昨日仍有提交。要注意兩件事：第一，協議是 PolyForm Noncommercial 1.0.0，README 自己寫了「OpenBot 不是自由軟體」，商用前先看條款；第二，README 的警告還在：agent 目前以高權限、無逐項確認的方式運行，能讀寫檔案、跑命令、上網、控制內置瀏覽器，只跑信任的任務、跑之前先備份。

它火在哪

第一，黑馬變慢火本身就是故事：10-27 那期它以黑馬身份出現，單日 +794 星、增幅 49.53%，當時只敢寫「單日增幅，持續性待觀察」；十天後總星從 2,397 漲到 6,050，漲了 2.5 倍，本週又 +2,085 星、週增幅 52.59%——觀察期結束了，它是真的燒起來了。第二，它是本期週榜裡本地優先味最濃的一個：資料留在本地、隊友跑在本地，連伺服器版都能自己架在家裡或 VPS 上，對「東西放自己手裡才安心」的人來說，這個賣點很對味。第三，fork 619 個、版本 117 個，出貨節奏沒斷過。

值得學什麼

「黑馬變慢火」本身就是一種判斷方法。單日爆發只能證明有人注意到了，十天後還在漲，才能證明有人留下來了——下次再看到單日漲五成的專案，先記下來，十天後回頭看一眼，比當天就下結論準得多。另一個值得偷的是它 README 裡 「本地優先，但不是離線」 的老實寫法：哪些連雲端、哪些留本地，專門開了一節講清楚，不裝「完全離線」也不藏「其實要聯網」，這種交代清楚邊界的做法，寫我們自己的工具說明時也該學。

我們怎麼用：我們派任務給 Hark、寫排程說明的思路，可以照它「一人一個工位＋任務佇列」的方式想：不同任務開不同工作區、各自排隊，別全擠在同一個對話裡互相打擾。真要試，先裝桌面版、只接一個 agent、跑不重要的任務——README 的高權限警告還在，只跑信任的任務、跑之前先備份；等它把權限收緊了，再談正經用。

怎麼裝起來試：從 GitHub Releases 下載對應系統的安裝包——macOS 下 OpenBot-*-arm64.dmg（Intel 用 x64 版），Windows 下 *-x64.exe，Linux 下 *-x86_64.AppImage（chmod +x 後直接跑）；想放家裡伺服器上 24 小時掛著，README 有一鍵安裝腳本和 Docker 寫法。先只接一個 agent 試水，別一上來就全接上。
