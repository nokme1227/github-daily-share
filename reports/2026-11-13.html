昨天才介紹過的 Modern Web Guidance，今天又回來了：一天 +1,875 星、增幅 63.99%，總星 4,805——昨天的 +799 已經是斷層第一，今天直接翻了一倍多。兩天合計 +2,674 星，總星從 2,866 漲到 4,805。

它到底是幹嘛的

基礎介紹見上一期（2026-11-12）：給 AI 程式工具裝的技能，npx modern-web-guidance@latest install 一行裝好，內含 250 個現代網頁特性指南，查指南用 search、取全文用 retrieve、掃老寫法用 legacy-scan .。今天只補新看點。第一，工具本身在變快：11-13 當天的提交把 legacy-scan 提速了 4.5 倍，還補了 .scss 掃描、Lit 模板解析、無障礙指南更新——等於一邊被圍觀、一邊還在修東西。第二，提交密度沒掉：11-13 一天就有 8 條提交進主線，維護節奏跟漲星速度對得上，不是漲完就丟著的專案。

它火在哪

值得學什麼

昨天講了「把最佳實踐寫成技能餵給 AI」和「評測驅動的剪裁」，今天補一條新的：熱度來的時候，順手把工具本身變快，熱度會自己接著漲。legacy-scan 提速 4.5 倍這種提交，放在平常沒人注意，放在漲星的當天，就是給新來的人一個「這專案還在動、而且越變越好」的證據。反過來看我們自己的工具站：新功能上線、關注度來的時候，是不是也該先把「正在動的東西」擺出來，而不是只發一篇說明？跟 Sure 那條「熱度用出貨接住」是同一課，只是這次的主角換成了 Google。

Veyra：GTA6 倒數五天，PS5 畫面先在電腦上「加料」

Likely7 / Veyra-NRVideo · GPL-3.0 協議 · C++ · Windows 11 · DirectX 12 · 目前版本 2.1.5 · 支援 NVIDIA 與 AMD 顯卡

插畫：Veyra 的位置在「擷取卡後面」——PS5 跑它的，電腦這邊把畫面再加工一遍。

一句話人話

一個 Windows 上的即時影像強化播放器：把本機影片、擷取卡、遊戲串流接進來，用顯卡即時做超解析度、降噪、HDR 和補幀，一天 +245 星、增幅 17.9%。它會火，時間點很關鍵——GTA6 11 月 19 日上市，只剩五天，專案簡介第一句就是「讓 PS5 的 GTA6 跑上 120FPS」。

它到底是幹嘛的

README 的定位寫得很直白：Real-time GPU Video Enhancement for Windows。功能分四塊：超解析（RTX Video SR、DLSS／FSR／XeSS 選項，2.1.2 還加了雙重超解析和「先放大再縮小」模式）、降噪 NR（節點式編輯，每層降噪強度、色彩參數可以獨立調，還能存成預設）、HDR 與色彩（HDR 寬色域還原、手動九項畫面控制）、補幀（Frame Generation，把低幀率畫面補到看起來更順）。來源支援本機影片、擷取卡、螢幕擷取，還有 PS5、Xbox 和 PC 串流（跟 Moonlight／Sunshine 相容）。匯出支援 MP4／MKV、多音軌、內嵌字幕。遊戲模式下 F7 截圖、F8 錄影。目前版本 2.1.5，GPL-3.0 開源，C++、DirectX 12，只跑 Windows 11。

它火在哪

一是時間點踩得太準：GTA6 11 月 19 日上 PS5 和 Xbox，預載已經開了，PS5 玩家這幾天都在找「怎麼讓畫面更好看」的方法，一個標題就寫著 GTA6 的工具正好撞上來。二是數字有東西撐：README 自己寫了下載量——可攜版累計 79,332 次下載（截至 11-08）、全部發佈檔案合計 103,337 次，不是只有星數好看。三是維護沒停：11-11 還有推送，2.1.2 到 2.1.5 一路都在修東西，連更新日誌都寫得鉅細靡遺。

值得學什麼

先講清楚兩件事，免得被標題帶著走。第一，「讓 PS5 的 GTA6 跑上 120FPS」是行銷話，不是字面意思：Veyra 強化的是擷取卡送進電腦的那路畫面，PS5 本體跑幾幀還是幾幀，它改不了主機的渲染——它做的是「看起來更順、更清晰」，不是「主機跑得更快」。第二，簡介寫的「DLSS 5」，README 裡沒有對應的具體說明，只列了 DLSS／FSR／XeSS 選項，先當專案自己的說法聽，別當成已經核實的功能。值得學的是另一面：它把「每一步的效果和代價」都寫出來了——README 連 RTX 5070 上每個特效要花幾毫秒都列出來，還老實寫「AMD 這邊沒有量到本地加速數字」；節點式管線（List／Node 兩種模式、每層參數獨立、預設可存）也是乾淨的設計，值得偷進我們自己的數據管線：每一步可看、可調、可回滾。

先說清楚：這是 Windows 11 專用工具，要吃顯卡效能，擷取卡、PS5 串流都要自己先接好；補幀和超解析是「看起來更好」，不是主機效能變強，別指望它讓 PS5 多跑出幀數來。GPL-3.0 開源，拿去改可以，但改完發佈要照 GPL 的規矩來。
我們怎麼用：跟 PS5 是直接相關的：GTA6 上市後，PS5 接擷取卡進電腦，Veyra 就是現成的「看片模式」——先試免費的可攜版，不用安裝，跑一圈看看補幀和超解析在自己這台電腦上的效果再決定要不要留。另一條是偷設計：它的 List／Node 節點管線——每一步獨立參數、預設可存、效果可量化——跟我們工具站的數據管線是同一種手藝，值得對照著看。

Sherlock：八年前的老工具，這週突然多了 14,381 顆星

sherlock-project / sherlock · MIT 協議 · Python · 總星 111,116（本週前基數 96,735）· 2018 年建立 · fork 數 12,856 個

插畫：Sherlock 做的事就這麼簡單——拿一個使用者名稱，去四百多個網站門口一個一個問「這人是不是你們家的」。

一句話人話

一個 2018 年就有的老工具：拿一個使用者名稱，去 400 多個社群網站上查它到底註冊過哪些帳號。本週 +14,381 星、週增幅 14.87%，總星 111,116——一週漲的星，比很多專案一輩子都多。

它到底是幹嘛的

用法簡單到只有一行：sherlock user123，它就去 400 多個網站上逐一查詢這個使用者名稱是否存在，結果可以輸出 CSV 或 xlsx，也能指定只查某個網站（--site）、走代理（--proxy）。安裝也是三選一：pipx install sherlock-project、docker run -it --rm sherlock/sherlock，或 Debian／Ubuntu／Homebrew／Kali 的社群套件。MIT 開源，Python 寫的，2018-12-24 建立，昨天（11-13）還有推送，fork 數 12,856 個。值得一提的是，它這週不是第一次出現在我們的視野裡：11-09、11-10 兩期的絕對榜，它分別以 +4,294、+2,387 拿過第一和第二——這週的爆發是連著好幾天燒出來的，不是某一天突然炸開。

它火在哪

一是「老樹開新花」本身就有傳播力：一個八年的工具，總星早就過了十萬，這週又多了 14,381 顆，說明它不是靠新鮮感，是靠「突然又有很多人需要它」。二是需求很實在：現在人人都在好幾個平台用同一個使用者名稱，想知道自己在外面到底留了多少足跡，查一次就知道了。三是維護證據很硬：八年時間、昨天還有推送，400 多個網站的規則要一直有人修——這種「一直在修」的老專案，漲勢通常不是曇花。

值得學什麼

「一個問題、一行命令、結果可匯出」，就是一個好工具的全部。Sherlock 沒有儀表板、沒有帳號系統，核心就是「查使用者名稱在不在」這一件事，但它把這一件事做到了 400 多個網站、還能輸出表格——功能窄、做得深、結果能帶走。另一個值得偷的是 「網站規則與程式分離」：400 多個網站的查詢規則是資料不是程式碼，網站一改規則，改資料就行，不用動主程式——這種「把常變的東西抽成資料」的思路，跟我們工具站把指標規則抽成設定檔，是同一種手藝。

我們怎麼用：最直接的用法，跟我們平常講的資料安全有關：拿自己的常用使用者名稱跑一遍 sherlock <你的使用者名稱>，看看自己在外面到底留了多少公開足跡——資料安全意識強的人，先知道自己露了多少，才知道該收哪裡。提醒一句：只查自己的帳號，別拿去查別人；它查的是公開註冊資訊，不是破解工具，別越界。

怎麼裝起來試：pipx install sherlock-project 裝好就能用；不想裝就 docker run -it --rm sherlock/sherlock 跑容器版；先拿自己的使用者名稱試一次，看看輸出長什麼樣，再決定要不要留著。

🔥 慢火榜 · 本週 +4,601 ⭐ · 週增幅 9.98% · 新面孔

agent-browser：給 AI 配一台「一次只動一個指令」的瀏覽器

vercel-labs / agent-browser · Apache-2.0 協議 · Rust · 總星 50,709（本週前基數 46,108）· 2026-01-11 建立 · fork 數 3,526 個

插畫：agent-browser 的核心迴圈就三步——看快照、按編號點、再看一次確認，瀏覽器全程開著。

一句話人話

一個 Rust 寫的命令列工具，讓 AI 用「一次一個 shell 命令」的方式開瀏覽器：先看一張帶編號的頁面快照，再按編號點，點完再看一次確認。本週 +4,601 星、週增幅 9.98%，總星 50,709。

它到底是幹嘛的

README 的定位是一句話：Browser automation for AI agents。核心迴圈是三個命令：agent-browser open example.com 開頁面、agent-browser snapshot -i 把頁面變成帶編號（@e1 這種）的緊湊文字、agent-browser click @e1 按編號行動，agent-browser get url 看結果、agent-browser close 收尾。瀏覽器在命令之間一直開著，所以每一步都是一次短短的 shell 呼叫。除了編號，也支援 CSS 選擇器、文字、XPath。背後是常駐的 daemon，透過 Chrome DevTools Protocol 控制瀏覽器，預設用 Chrome for Testing，也能接正在跑的 Chrome、iOS 模擬器裡的 Mobile Safari、或雲端瀏覽器。還自帶技能包（agent-browser skills get core）和 MCP 伺服器（agent-browser mcp），裝進 agent 流程裡就能直接用。Apache-2.0 開源，2026-01-11 建立，昨天（11-13）還有推送，fork 數 3,526 個。

它火在哪

一是數字是整週燒出來的：本週 +4,601 星，週增幅 9.98%，基數 46,108——這種體量的專案一週漲一成，靠的是持續有人用、持續有人推。二是它踩在正熱的點上：AI 助手要自己開瀏覽器幹活，已經是這兩個月榜單上的常客題材（從 agent-desktop 到 OpenBot 都在講同一件事），agent-browser 補的是這條鏈上最實用的那一環——「怎麼讓 AI 可靠地點到東西」。三是設計上有個小聰明：點不到就老實報錯——目標被遮住、被禁用、超出可視範圍時，點擊會失敗而不是謊報成功，這種「寧可失敗也不瞎報」的脾氣，正是 agent 工具最缺的東西。

值得學什麼

「快照 → 按編號行動 → 再快照確認」，就是一個可驗證的迴圈。AI 最容易出的問題不是「不會點」，是「點完不知道自己點對了沒有」——agent-browser 強迫每一步都重新看一次結果，確認了再往下走。這個思路直接能偷進我們的復核流程：每一步操作之後，先看一眼結果再往下走，別一口氣跑完才發現第一步就錯了。另一個值得偷的是 「技能跟著版本走」：CLI 自帶的技能包跟安裝的版本一致，說明書永遠不會比工具舊——我們工具站的說明文件，是不是也該跟著版本一起發？

我們怎麼用：跟我們平常的自動化場景直接相關：以後要讓 AI 助手自己開瀏覽器查資料、核對頁面，與其讓它猜座標、猜選擇器，不如用這種「快照編號」的方式——每一步可驗證、可重試。學它的迴圈設計，比裝它本身更值錢：我們的排程腳本跑完一步，也該先看一眼結果再往下走。

怎麼裝起來試：npm install -g agent-browser，第一次再跑 agent-browser install 下載 Chrome for Testing；不想裝就 npx agent-browser open example.com 直接試；裝完先跑 agent-browser snapshot -i 看一眼快照長什麼樣，再決定要不要接進流程。
