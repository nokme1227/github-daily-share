PaperOrchestra：第三天了，還是它——三天 +3,010 星，總星從 1,471 漲到 4,249

google-research / paper-orchestra · Apache-2.0 協議 · Python · 2026 年 5 月建立 · 11-15 仍有更新進主線 · fork 531

插畫：第一天試音、第二天開演、第三天直接加場——同一支樂隊，三天之內觀眾席翻了快三倍。

一句話人話

Google Cloud AI Research 的多 agent 論文寫作框架，連莊第三天：今天 +1,529 星、增幅 56.21%，三天合計 +3,010 星，總星從 1,471 漲到 4,249。基礎介紹見 11-16 期，今天只補兩個上一期沒寫的實用細節：它到底怎麼跑、以及跑之前要先準備什麼。

它到底是幹嘛的

基礎介紹見 11-16 期：五個 agent 分工（大綱、文獻、寫作、潤色、畫圖），把點子跟實驗記錄寫成能投稿的 LaTeX 稿件；11-17 期補了 autoraters/ 自動評分腳本跟 arXiv 論文背書。今天補跑法：兩條路，一是 ./paper_writing_cli.sh 一鍵跑，二是直接下 Python CLI——python paper_writing_cli.py --raw_materials_dir /你的素材/ --latex_template_dir /模板/ --output_dir /輸出/ --use_plotting true，倉庫自帶 CVPR 2025 模板，換模板就換個目錄。寫手跟評分用的模型還能分開指定：--writer_model_name 管寫作跟文獻，--reflection_model_name 管反思，寫手跟考官用不同模型，分工可以玩得更細。另外還有個 Streamlit 互動 demo，不想先下 CLI 的人可以先在網頁上看流水線長什麼樣。

它火在哪

一是「連莊三天、一天比一天多」本身就是罕見走勢：+306、+1,175、+1,529，一天比一天兇，說明這不是一天的熱搜衝榜，而是第一批人試完覺得真能寫，第二批、第三批接著進場。二是它踩的痛點夠真：寫論文這件事，從點子到投稿中間那段最磨人的活，全世界的研究生都懂。三是它有正式論文背書：arXiv:2604.05018 掛在那裡，可信度不是只憑 README 撐著。

值得學什麼

最值得偷的還是上一期那句：「產出物要自帶評分器」——寫完論文，同一套倉庫裡的自動評分腳本立刻打分，產出跟評分長在同一個地方，品質才不會只靠感覺。今天再補一招：「寫手跟考官用不同模型」——--writer_model_name 跟 --reflection_model_name 分開指定，寫的人跟審的人不共用同一雙眼睛。換到我們的雙助手流程想一想：研究跟核實本來就不該是同一個人，連模型都分開，才是認真的分工。

我們怎麼用：對照我們的雙助手流程：研究、核實、裁決、結算四步，現在是人手推進。PaperOrchestra 的 autoraters/ 給了一個現成的樣子——把檢查清單寫成腳本，先讓機器跑一遍確定性的分，再交給人審。想動手試的話還是那句老實話：要自備 Gemini 或 OpenAI 的 API key，寫論文用的資料集不在倉庫裡（README 寫明之後另外發布），別空手去跑；先玩 Streamlit demo 看看流水線長什麼樣，再決定要不要接進來。

SkillEvaluator：給 AI 技能打分的驗貨員，昨天剛走，今天就被請回來

NVIDIA / SkillEvaluator · Apache-2.0 協議 · Python · 2026 年 6 月建立 · 11-18 當天仍有更新進主線 · fork 516

插畫：SkillEvaluator 的三層關卡——第一層不用花錢，第二層防重複，第三層動真格：裝上技能，到底有沒有變強？

一句話人話

NVIDIA 的 AI agent 技能評測框架：檢查技能寫得合不合格、安不安全、有沒有跟別的技能撞衫，最後還真刀真槍測一次——裝上這個技能，agent 到底有沒有變強。11-16 期拿過第一（+953、55.76%），昨天跌出主榜，今天 +323、9.55% 又回來了。基礎介紹見 11-16 期，今天補它的三層結構跟怎麼上手。

它到底是幹嘛的

先說背景：agent 技能就是一包指令加配套檔案（按 agentskills.io 的規範），現在滿天飛，寫得好壞沒人管。SkillEvaluator 就是給技能做的品管線，分三層：第一層是靜態檢查，500 多條規則加檢測模式，不用模型、不用 API key，skillevaluator validate ./my-skill --tiers 1 就能跑——品質、格式、版本、個資、授權、Unicode、腳本 lint 全包，安全檢查還拉了 SkillSpector、Gitleaks、Bandit 這些現成工具。第二層是去重：語意重疊檢測，看看你的技能是不是跟別人寫的重複了。第三層最狠：真跑一次 agent，對比裝技能跟不裝技能的任務成績，量出「技能到底帶來多少提升」。裝法也簡單：pip install skillevaluator（Python 3.12–3.14），想進 CI 就跑 skillevaluator ci init，它會直接在你的 GitHub 倉庫開一個設定 PR，之後每次改技能都會自動過一遍品管。另外還有個 harness-check：先測你的技能在 Claude Code、Codex、OpenCode 這些工具裡到底載不載得起來，載不起來就先別談品質。

它火在哪

一是它踩的時機準：技能滿天飛的當下，第一個出來認真做「技能品管」的大廠工具，大家都想看看標準長什麼樣。二是第一層不用花錢：500 多條靜態規則不用模型就能跑，門檻低到隨手就能試，試完覺得有用再往下走。三是它有論文跟官方文件背書（arXiv:2608.20614，docs.nvidia.com），不是一個隨手丟出來的玩具，進 CI 也不怕沒人維護。

值得學什麼

最值得偷的是 「分層檢查，便宜的先來」：不用模型就能查的，先用靜態規則查；要花錢、要跑真 agent 的，留到最後一層。很多人做檢查流程，一上來就全交給模型，又貴又慢。SkillEvaluator 的分法很值得抄：能寫成規則的先讓機器查，查完還站得住的，才值得花模型去評。另一招是 「先測載不載得起來，再談寫得好不好」：harness-check 先確認技能在各家工具裡能被載入，載不起來，後面 500 條規則全是白搭——這跟我們先核實數字再寫結論，是同一個道理。

我們怎麼用：我們的工具站跟報告流程裡，技能跟檢查清單越來越多（六大指標計分、P1 自查、實用複核），正好缺一個「檢查清單本身對不對」的品管。先跑 pip install skillevaluator，拿它去掃我們現有的技能文件，看看 500 多條靜態規則會挑出什麼毛病——不用 API key、不用改架構，掃完再決定要不要把 skillevaluator ci init 接進倉庫，讓每次改技能都自動過一遍品管。第三層的實測思路也可以偷：以後改檢查流程，先量「改完有沒有少錯漏」，別只憑感覺說變好了。

Arcane：長得好看的 Docker 管家，正在把 Portainer 的老用戶一個一個接走

getarcaneapp / arcane · BSD-3-Clause 協議 · Go（後端）＋ SvelteKit（前端） · 2025 年 4 月建立 · 11-18 當天仍有更新進主線 · fork 561

插畫：Arcane 的打法——主機上一個面板，遠端主機裝個 agent 就能一起管，compose 檔案還能走 Git 同步。

一句話人話

一個自架的 Docker 管理面板：容器、映像檔、磁碟區、網路、備份、自動更新，通通在一個網頁裡管，還能透過 agent 遙控別台主機上的容器。昨天 +654、7.56% 排在主榜外第四，今天 +547、5.93% 正式入榜，總星 9,778，快要破萬了。

它到底是幹嘛的

說白了就是 Portainer 的挑戰者，專門給在家裡架伺服器的人用的。功能清單很齊：管 Docker 專案（compose 堆疊）、容器、映像檔、映像檔建置、磁碟區、網路、備份、自動更新，compose 專案還能走 Git 同步，改檔案直接進版控；想管別台主機就裝個 agent，Swarm 叢集也支援；手機 App、GPU 監控、通知、反向代理、漏洞掃描這些也都有。裝法照倉庫的範例 compose 檔：映像檔是 getarcaneapp/manager:latest，掛 /var/run/docker.sock，開 3552 埠，設一個 ARCANE_ENCRYPTION_KEY 當加密金鑰，docker compose up -d 就起來了。現在主線是 v3 版，舊的 2.x 還留在 release/2.x.x 分支。

它火在哪

一是它正好踩在「Portainer 換人潮」上：官方文件站首頁掛了一整排 r/selfhosted 的真實評論，清一色是「從 Portainer 換過來，介面更好用、速度更快、自動更新不用再裝 Watchtower」。二是它的細節是衝著自架族的痛點去的：compose 檔案可以直接在網頁裡改、改完同步回檔案，還能走 Git；容器更新會檢查相依性，不會一個一個亂升。三是它活得夠勤：2025 年 4 月建倉到現在還在頻繁更新，v3 剛出，文件、手機 App、GPU 監控一樣都沒少，不是那種紅一陣子就躺平的專案。

值得學什麼

最值得偷的是 「把別人的痛點寫進自己的首頁」：Arcane 的官網不吹自己多強，直接貼一整排自架族的真實評論——「比 Portainer 快」「不用 Watchtower 了」「compose 可以走 Git」——每一句都是在對 Portainer 用戶說話。想學行銷，不用看書，看這個首頁就夠了。另一招是 「更新要帶相依性檢查」：容器自動更新不是一個一個升，升之前先看誰依賴誰，這種「慢一點但穩一點」的取捨，換到我們的工具站排程也一樣：寧可檢查多一步，也不要半夜把頁面推壞了。

我們怎麼用：家裡的機器不少（樹莓派、軟路由、DGX Spark、甲骨雲上的免費實例），容器一多，靠命令列一個一個管遲早會亂。Arcane 可以先裝在其中一台上試：照倉庫的範例 compose 檔起一個容器，3552 埠開起來，家裡其他主機裝個 agent 就能一起管，compose 專案走 Git 同步，改檔案有版控可追。提醒一句：它要掛 /var/run/docker.sock，等於給了它整台主機的 Docker 控制權，先在不重要的機器上試，跑順了再考慮接管主力機器。
