ThinkRail：别再让 AI 每次开工都失忆，给它一本活的规格书

JetBrains / thinkrail · Apache-2.0 · 围绕 pi 编程助手的 agentic IDE · 最近提交 2026-10-29

插画：ThinkRail 的三件套——隔离工作区、真 IDE、活的规格图，缺了哪件，AI 都容易越干越偏。

一句话人话

JetBrains 官方孵化的一个 IDE：不是再给你一个聊天框，而是把 pi 助手放进一个能并行开工、能看 diff、能提 PR 的真工作台里，而且它会记事。

它到底是干嘛的

核心就三件东西。第一，隔离工作区：把一个 git 仓库切成多个 worktree 工作区，每个工作区有自己的分支和目录，几个助手并行干活互不踩脚，好的分支合进来，烂的删掉，完事的工作区还会自己“归档上架”，要用时再拿回来。第二，真 IDE：可分屏的 Monaco 编辑器、带 git 变更标记的文件树、终端、文档，都跟着当前工作区走；还能在文件和 diff 上留锚点评论，直接当成结构化上下文发给对话。第三，规格当真理：一串互相连接的 SPEC.md 文件就放在代码旁边，助手通过专用的 spec 工具读写维护，意图不会随着会话结束就蒸发；另外还有可移植的 Agent Skills、发 PR 的工作流、MCP 服务器接入，以及对话里直接问你的选择题、画前后对比图这些工具。装法 README 里写得很直白：桌面版下对应平台的安装包，或者命令行 curl -fsSL https://raw.githubusercontent.com/JetBrains/thinkrail/main/install.sh | bash，再跑 thinkrail ~/code/my-repo；它需要 git 和一个模型供应商（JetBrains AI 登录，或你自己的供应商凭证），它自己不设账号。

它火在哪

一是出身硬：JetBrains 官方账号的孵化项目，不是个人练手作，609 次提交、124 个版本，昨天还有新提交，不是发完就躺平的库。二是它戳中了一个真痛点：现在大家不是缺 AI 助手，是缺“助手干了三天还记得当初为什么这么定”的办法——规格图就是冲着这个来的。三是它不绑死一种用法：桌面 App 和浏览器版是同一套引擎，状态都在 ~/.thinkrail，装完就能先拿一个仓库试水，不用先交出整个工作流。

值得学什么

把“意图”写进仓库，而不是写进聊天记录。很多 AI 流程的问题不是模型不够聪明，是每次开新会话都要把背景、规则、禁忌重新讲一遍，讲漏了就跑偏。ThinkRail 的做法值得抄：意图要有一个固定落点（SPEC.md），而且要让助手自己维护它，人只负责改错和拍板。

我们怎么用：先别急着换主力开发环境。拿工具站仓库的一个副本试一招：开一个隔离工作区改一页（比如五线谱页），同时在仓库里放一份 SPEC.md，把“工具站是给谁查数据的、每页的口径、不能做成什么样”写死，看助手下一会话还用不用你重讲。这一招如果管用，再把它推广成个股报告复核流程的台账：基本面、筹码、技术位阶各一路的结论依据和待复核项，都进规格图留档，而不是只留在某次对话里。提醒一句：它要接你自己的模型供应商，凭证只走你自己的供应商登录，别随手贴进仓库配置文件里。
