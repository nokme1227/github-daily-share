LoopForge：AI 寫程式不稀奇，照 SOP 交件、還要人點頭才稀奇

Tencent / LoopForge · MIT 協議（README 標示）· Go · 自架工作室 · 2026 年 7 月建立 · 11-15 當天仍有更新進主線

插畫：LoopForge 的邏輯就這麼一條線——需求進來，分工做完，人點頭，東西才出去。SOP 就是把這條線寫死。

一句話人話

騰訊開源的自架工作室：你跟 Main Bot 講需求，它在 Docker 沙箱裡叫一群 coding agent 分工幹活，幹完開 PR；做法跑順了就存成 SOP，下次照表操課。一天 +484 星、增幅 49.74%，總星 1,457，基數只有 973——小專案，大增幅。

它到底是幹嘛的

有兩種幹活方式。跟 Main Bot 聊天：講需求、@ 角色、@ 技能、@ 倉庫，Main Bot 開一個對話工作區（Docker 沙箱加你的倉庫），叫專案角色當子代理去幹，交件是 PR 或直接合併進共用分支。跑 SOP：SOP 就是一套寫死的標準流程，由 Agent、Script、Human-gate、子 SOP 四種節點按順序跑，每個節點在自己的沙箱裡；內建後端、前端、修 bug、產品四種 starter SOP。兩條路都綁在同一份「需求」上，所以不管哪條路改的東西，都能回頭對上當初問了什麼、成本多少。幹活的 agent CLI 有十種：CodeBuddy、Codex、Claude Code、OpenCode、Cursor CLI、Antigravity、Kimi Code、Pi、DeepSeek Harness、ZCode，LoopForge 負責在外頭加上角色、沙箱、檢查點和歷史紀錄。裝起來也不囉嗦：git clone https://github.com/Tencent/LoopForge.git，cd LoopForge，./start.sh——它會拉 GHCR 的 release 映像、起 MySQL 和平台服務，預設聽 0.0.0.0:8090，主機不用另外裝 Go 和 Node.js。

它火在哪

一是它戳中了「AI 寫程式」的下一個痛點：叫 agent「修個 bug」，結果每次都不一樣——可能跳過計畫、忘記測試、自己審自己的程式碼、做到一半沒人發現。LoopForge 的答案是把流程寫死：同一套 SOP、同一批關卡、每一次需求都一樣跑。二是「人要點頭」這件事擺在明面上：Human-gate 節點就是讓你看報告、點批准，或把工作打回指定步驟重做，不是事後才發現出包。三是自架這點很對胃口：跑在自己的伺服器上，程式碼、倉庫、紀錄都在自己手裡，MIT 協議。四是數字結構乾淨：基數 973 還很小，一天 +484 就是近五成增幅，不是大專案靠體量撐場面。

值得學什麼

「好做法要寫成 SOP，下次照表操課」——這句話直接可以抄。很多團隊的 AI 流程都卡在同一個地方：某次跑得好，全靠那次的提示詞寫得好，下次換個人、換個需求就打回原形。LoopForge 把「跑順的做法」存成 SOP，裡面連「哪一步要人批准」都寫進去，這就是把經驗變成資產。另一招也值得偷：角色分開——規劃、實作、審查、測試各有自己的提示詞、執行器、模型和規則，一個角色只幹一件事，錯了也知道是哪一環的鍋。

我們怎麼用：先別急著整站搬家。它的 SOP 概念可以直接對照我們的雙助手流程想一想：研究、核實、裁決、結算四步，本身就是一條 SOP——差別只在我們現在是人手推進，它是寫成節點、跑在沙箱裡。想動手的話，先跑它內建的 demo SOP「Platform check · script & approval」：一個腳本寫報告、然後停在批准步驟等你點頭，五分鐘就能看到 Human-gate 長什麼樣。自架在自己的機器上跑，資料不外流，這點跟我們的工具站是同一路數。

Modern Web Guidance：第四天了，漲幅回落，熱度沒掉

GoogleChrome / modern-web-guidance-src · Apache-2.0 協議 · TypeScript · 250 個現代網頁特性指南 · Chrome、Edge、Firefox、MDN 四方聯手維護

插畫：第四根柱子跟第三根幾乎一樣高——爆發過後，熱度站住了，沒往下掉。

一句話人話

第四天了，還在第二名：一天 +1,220 星、增幅 20.63%，總星 7,133。四天合計 +5,119 星，昨天跟今天的新增幾乎一樣（+1,225 對 +1,220），這不是曇花一現，是站住了。

它到底是幹嘛的

基礎介紹見 11-12、11-13、11-14 三期：給 AI 程式工具裝的技能，npx modern-web-guidance@latest install 一行裝好，內含 250 個現代網頁特性指南，查指南用 search、取全文用 retrieve、掃老寫法用 legacy-scan .。今天只補新看點：第一，動手的人還在增加：fork 數從 11-13 的 268 個、11-14 的 401 個，漲到今天的 599 個——看熱鬧的人和動手裝的人一起來，而且動手那批的增速沒掉。第二，增幅回落得很體面：從 63.99% 的高峰回到 20% 出頭，連著兩天守在同一個量級，這才是正常熱度的樣子：第一天嚐鮮、第二天口碑爆發、第三、四天還能守住，就是真的有人在用。第三，維護沒停：11-15 當天仍有更新進主線。

它火在哪

一是「連莊四天」本身就很罕見：日榜是個喜新厭舊的地方，同一張臉連著四天站前兩名，說明它不是一陣風。二是它踩在兩個熱點的交叉點上：「AI 寫程式」加上「瀏覽器四方聯手背書」，兩個題材各自都能漲，疊在一起就更不用說。三是數字結構健康：總星漲、fork 也漲，而且 fork 的增速比總星還猛——這批人不是來圍觀的，是來搬東西回去用的。

值得學什麼

前三天講了「把最佳實踐寫成技能餵給 AI」、「熱度來的時候順手把工具變快」、「第三天還在靠的是東西真的有用」，今天補第四條：看一個專案是不是真的站住，別只看星數，看 fork。星是「我覺得不錯」，fork 是「我要拿回去用」——連著四天 fork 都在漲，說明留下來的人是真的在用。對照我們自己的工具站：新功能上線後，看的不該只是點閱，是不是有人真的拿去查、拿去用。

我們怎麼用：用法跟前三天一樣：還沒跑過 npx modern-web-guidance@latest legacy-scan . 的，今天掃一遍工具站程式碼——現在掃全站也不心疼了。它教的是「寫法」，不是「長相」——頁面長什麼樣，還是 Hallmark 那套說了算。

Claude Trading Skills：第二天，流程寫成檔案，機器也讀得懂

tradermonty / claude-trading-skills · MIT 協議 · Python · Claude Skills 架構的交易流程工具包 · 僅供研究、不是投資建議

插畫：這專案最值錢的一招，是把「怎麼做功課」寫成一份機器可讀的清單——技能、關卡、產出物，一行都不少。

一句話人話

給 Claude Code 的投資流程技能包，第二天還在榜上：一天 +707 星、增幅 14.68%，總星 5,522。先說清楚：它不給明牌、不下單、不承諾賺錢——README 一開頭就把這三句話寫明白了，教的是「怎麼做投資功課的流程」。僅供研究、不是投資建議。

它到底是幹嘛的

基礎介紹見上一期：給時間不夠的個人投資者，長期投資、ETF、股息股為主，紀律波段為輔；目標不是把買賣決定外包給 AI，而是把市場檢視、風險管理、交易計畫、交易日誌、持續改進結構化。入門有五條路：market-regime-daily（15 分鐘每日盤檢）、core-portfolio-weekly（每週長期組合檢視）、swing-opportunity-daily（只在風險允許時找波段機會）、trade-memory-loop（每筆平倉交易都留記錄、做檢討）、monthly-performance-review（每月績效檢討、調整規則）。今天只補一個新看點：每條工作流都有一份機器可讀的清單（workflows/ 底下的 YAML），裡面白紙黑字寫著用哪些技能、過哪些決策關卡、產出哪些東西——流程不是寫在文章裡給人看的，是寫成檔案給機器照著跑的。沒付費數據 API 也能起步：五個技能用公開 CSV、圖表截圖、本地檔案就能跑。安裝是 clone 下來，或從 skill-packages/ 拿預打包的 .skill 上傳到 Claude 網頁版 Skills 頁。README 還有日文版，照顧的讀者不只英文圈。

它火在哪

一是踩在兩個熱點的交叉點上：「Claude Skills 生態」加上「投資流程」，兩個題材各自都能漲。二是它反其道而行：別的投資工具都在比「訊號多準」，它一開頭就說「我不給訊號」——在滿是明牌的圈子裡，「不給明牌」本身就是一種信任狀。三是它的使用門檻想得很周到：免付費 API 的起步路徑寫在 README 最顯眼的位置，沒訂閱也能先跑起來，願意試的人就多了。四是第二天還在漲：昨天 +556、今天 +707，新增比昨天還多，說明第一天進來的人沒走，第二天又帶了新朋友。

值得學什麼

昨天講了「流程比判斷值錢」和 trade-memory-loop、drawdown-circuit-breaker 兩招，今天補第三招：流程要寫成機器可讀的檔案，不要只寫在文章裡。文章是給人看的，看完還是得憑感覺執行；清單檔案是給流程跑的——用哪些技能、過哪些關卡、產出什麼東西，一行都不少，換個人、換一天跑，結果都一樣。這招換到我們的個股報告復核流程裡就是：把「研究 → 核實 → 裁決 → 結算」寫成一份清單，誰跑都一個樣，不靠當天的心情。

我們怎麼用：先潑一盆冷水：別拿它來選股下單，更別拿計劃資金實盤——先模擬盤走一段時間，流程跑順了再說。值得偷的是它的工作流設計：market-regime-daily 的 15 分鐘盤檢清單，可以對照我們的六檔復核流程改一版「每日盤檢」清單；workflows/ 那種「技能＋關卡＋產出物寫成檔案」的做法，可以對照我們的辯論流程想一想——研究手、核實手、裁決三步，要是也寫成一份清單，下一場辯論就不用每次從頭交代規則。僅供研究、不是投資建議——這句話，作者寫在 README 裡，咱們也原樣貼在這裡。
