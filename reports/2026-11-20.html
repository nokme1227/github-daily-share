一句話人話

開源的 AI 影片剪輯桌面工具：貼一個長影片連結，選好要發的平台，它自動剪出短影片，連字幕、封面和發文文案一起給你。一天 +983 星、增幅 8.80%，總星 12,156。

它到底是幹嘛的

README 的定位是一句話：一個連結，一鍵出片。流程分三步：先按平台的畫幅與時長要求，從長影片裡按評分自動挑出至多 10 條合格片段，其餘列為備選；每條成片都帶封面、標題、簡介、話題和 ZIP 發布包；抖音／小紅書預設訪談式、TikTok／Reels／Shorts 預設滿屏播客式，B 站／YouTube 走橫版，畫面會跟著說話的人走。剪輯、取景與渲染都在本機完成，分析模型可以自選，字幕能用作者自帶字幕、本地 Whisper／SenseVoice，或已配置的雲端轉寫；用雲端分析會把相關字幕與文案送上雲，畫面理解或參考幀生圖會送抽樣畫面——README 專門寫了一節隱私說明，交代什麼東西會離開本機。桌面、CLI 與 MCP 共用同一條一鍵出片鏈路：autoclip produce talk.mp4 --srt talk.srt --platform douyin --portrait-style podcast --json，已有字幕可用 --srt 跳過轉寫；MCP 則是 autoclip mcp，還能接進 OpenCode。軟體本身免費，雲端模型按量計費——README 還老實貼了一張自家實測的費用表：1 小時 43 分的英文訪談轉小紅書，7.5 分鐘出 10 條，文字模型費用估算人民幣 0.09 元（這是 README 自稱的實測數字，我們沒親自驗證過，實際帳單以所選服務商為準）。

它火在哪

一是「一鍵出片」這四個字正好踩在需求上：播客、訪談、課程這類長內容，剪成短影片是最花時間的髒活，誰先把髒活包成一條流水線，誰就先被注意到。二是它沒有把東西都推上雲：剪輯渲染留在本機，模型可以自選、字幕可以本地轉寫——對「東西放自己手裡才安心」的人來說，這個分法很對味。三是桌面、CLI、MCP 三條入口共用同一條鏈路，寫一次、到處能用，想批量處理、想接進 agent 流程都不用換工具。

最值得偷的是 「一條鏈路，三種入口」：桌面給人點、CLI 給腳本跑、MCP 給 agent 叫，底下卻是同一條一鍵出片的流水線——介面可以有很多個，核心邏輯只有一份，改一處、三處都跟著變。另一招是 「費用敢寫具體數字」：README 不寫「超便宜」，寫的是 1 小時 43 分的片子、7.5 分鐘、0.09 元——數字具體、條件寫清（只算文字模型、不含轉寫與生圖），反而更讓人信。我們寫工具站報告也一樣：數字具體，才有人信。

我們怎麼用：手邊有長影片素材（比如會議錄影、訪談、教學）想剪成短片發的人，可以先從桌面版試起：Releases 頁下載安裝包（自帶 Python 和 FFmpeg），首頁先點「用示例項目看看效果」，不用 API Key 就能看成片長什麼樣，再決定要不要貼自己的片子。對我們的工具站來說，更值得偷的是它的架構：桌面、CLI、MCP 共用一條鏈路的做法，正好對照我們「報告產出」那條線——同一份數據，頁面、腳本、agent 複核三種入口能不能也共用同一套邏輯，少寫三份重複程式碼。

Ghost-Downloader-3：下載器的集大成者，一個 App 頂五個

XiaoYouChR / Ghost-Downloader-3 · GPL-3.0 協議 · Python · Windows／macOS／Linux／Android 四平台 · fork 數 837 個

插畫：Ghost-Downloader-3 的賣點就一句話——以前要裝五個下載器，現在一個就夠了。

一句話人話

號稱「下載器的集大成者」：HTTP、磁力／BT、FTP、M3U8、DASH、eD2k 全包，YouTube 和 B 站還能選片段、選畫質、抓字幕。一天 +1,082 星、增幅 8.59%，總星 13,676——昨天它還是空榜那期最接近門檻的一名（+449、3.67%），今天新增直接翻倍多，增幅一次過線。

它到底是幹嘛的

README 的定位也是一句話：The only downloader you need。功能分四塊：第一，協議全——HTTP、Magnet/BT、FTP、M3U8、MPEG-DASH、eD2k，YouTube 和 B 站支援片段選擇、任意畫質、字幕、播放清單與多集連載，GitHub 和 HuggingFace 還有鏡像加速。第二，下載體驗——智慧分塊不用合併檔案、自動偵測頻寬、斷點續傳進度不丟，瀏覽器擴充功能會在影片旁邊跟一個下載按鈕，登入狀態也能帶過去。第三，四平台原生——Windows、macOS、Linux、Android 都有，Android 版還能錄 M3U8 直播、背景繼續下載。第四，能接進流程——相容 aria2 的 RPC API 給第三方工具呼叫，下載中途還能改連結、改標頭、改代理；另外有個 ghd 命令列工具（在設定裡安裝）：ghd probe <url> 先預覽、ghd add <url> --select 0,3 -o ./downloads 只抓指定的檔案、ghd wait tsk_0123 等它下完。GPL-3.0 開源，昨天（11-20）還有推送。

它火在哪

一是「一個頂五個」的需求很真實：家裡機器多、常要抓檔案的人，早就受夠了每個協議裝一個工具，全部收進一個 App，連外掛生態（Feature Packs）都一起做了。二是連漲有連續性：昨天 +449 星已經是全場絕對新增第四多，今天再 +1,082 星——兩天加起來超過 1,500 星，這不是一天的新聞，是有人持續在裝、持續在推。三是細節做得像回事：下載中途能改連結和代理、進度永遠不丟、還留了 aria2 相容的 RPC 給別人接——這種「讓別人也能接進來」的設計，是工具能活得久的關鍵。

值得學什麼

最值得偷的是 「把別人的生態也當成自己的介面」：aria2 相容的 RPC API，讓現成的第三方工具不用改就能接上它——不用自己從零攢生態，先把別人的生態借來用。另一招是 「命令列跟圖形介面是同一套任務」：ghd 的 probe、add、wait 操作的，就是圖形介面裡的那批下載任務——介面可以有很多個，任務只有一份。這個思路跟 AutoClip 的「一條鏈路三種入口」是同一課，只是換了一個專案講。

先說清楚邊界：這是個下載工具，能下載什麼、該不該下載，要看內容本身的授權與平台規則——只抓自己有權取得的內容，別拿它去繞過付費牆、抓盜版或侵犯著作權。它本身不是惡意程式、詐騙、色情或政治敏感內容，所以照常入選；但怎麼用，是使用者的責任。
我們怎麼用：家裡機器多、常要抓檔案的人（比如抓開源數據集、抓模型權重、抓工具站要用的公開資料），可以先從 Releases 頁下載桌面版試試；常寫腳本的人更值得看 ghd 那套命令列：ghd probe 預覽、ghd add 下載、ghd wait 等完——排程腳本裡要抓檔案，照這個介面寫就行。對我們的工具站來說，GitHub 和 HuggingFace 鏡像加速那段也值得記一筆：以後抓 FinMind 以外的公開數據源卡住時，換個鏡像、換個下載路徑，有時候比調程式更管用。

README 的定位是一句話：Plannotator Inbox is the missing review layer between you and multi-agent work。它透過外掛、hook 與命令直接接進 agent：Claude Code、Codex、Copilot CLI、Gemini CLI、OpenCode、Kiro、Droid、Amp、DeepSeek Harness、Pi 都支援；agent 提出決策、計畫、HTML 原型或做完工作時，瀏覽器裡就打開審稿介面，你標註、留言，回饋直接送回 agent。功能分三塊：第一，審文件、計畫與 agent 訊息——在計畫、規格、訊息、HTML 上批註，送回 agent；第二，程式碼審查——看本地改動或遠端 PR 的 diff、逐行留言、提修改建議，支援 Git、GitButler、Jujutsu（jj）、Perforce、GitHub、GitLab，大改動還能走「引導式審查」，由 agent 先把 diff 排成重點在前的章節；第三，Plannotator Inbox——一個本地窗口收所有 agent 留下的訊息、問題、檔案與引導式審查，你點一下回答問題、批註檔案，按 Send 就好，不用一直開著 agent 的對話等它，其他 agent 則透過 MCP（plannotator inbox mcp）接進來。安裝是一個安裝器搞定大多數 agent：curl -fsSL https://plannotator.ai/install.sh | bash，它會裝 plannotator 二進位檔、自動偵測已裝的 agent 並配好 hook、技能與斜線命令；只想拿二進位檔的話可以加 --minimal，什麼都不多裝。昨天（11-20）還有推送，fork 數 1,389 個。

值得學什麼

「審稿層」這個位置，值得單獨做成一層。我們的雙助手流程（一個做研究、一個做核實、最後我終審）其實就是一層人肉審稿層——Plannotator 把它做成了產品：agent 交件、人在瀏覽器裡批註、回饋回到 agent 的下一輪，而且不用一直開著對話等。另一個值得偷的是 「引導式審查」：大改動先由 agent 把 diff 排成「重點在前」的章節，人再一章一章看——審查的順序本身就是一種設計，先看重要的，再看瑣碎的。

我們怎麼用：這一個跟我們的日常流程最像：研究手交草稿、核實手交核對表、終審拍板——中間缺的正是一個「人在旁邊看著、畫著、回著」的地方。現在流程還小，靠對話就能管；等到 agent 越來越多、交件越來越頻繁，再考慮裝一個這樣的審稿層。學它的迴圈設計，比裝它本身更值錢：每份草稿交上來，先排「重點在前」的審查順序，再逐項核對——跟我們「數字先核實再寫、錯誤逐項回覆」的規矩，是同一種手藝。

怎麼裝起來試：curl -fsSL https://plannotator.ai/install.sh | bash 裝好並自動接進已裝的 agent；只想先拿二進位檔試試的話，加 --minimal 什麼都不多裝；裝完先跑 plannotator inbox 看一眼收件匣長什麼樣，再決定要不要接進流程。
