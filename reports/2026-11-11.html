Astryx：三連冠了——百分比在降，每天還是穩穩加三千星

meta / astryx · MIT 協議 · TypeScript · 目前 Beta · 基於 React 19+ 與 StyleX

插畫：增幅一天比一天小（19.99% → 15.87% → 12.87%），但柱子一根比一根只矮一點點——每天三千星的絕對新增沒掉，這才是連莊的底氣。

一句話人話

同一個名字第三天出現在第一名。Meta 的設計系統 Astryx 連莊三天，今天再 +2,842 星、增幅 12.87%，總星衝到 24,918——三天合計新增 9,277 星。

它到底是幹嘛的

基礎介紹前兩期都講過了（詳見 2026-11-09、2026-11-10 期）：開源設計系統，Meta 內部用了八年、撐著 13,000 多個應用，150+ 無障礙元件、七套主題、深色模式、CLI 管家，人跟 AI 共用同一套工具。今天只補一個前兩期沒提的細節：README 最頂上有一行註解——SYNC CONTRACT: Architecture changes require documentation updates，意思是架構改了，文件必須跟著改，這是寫進倉庫的契約，不是口頭提醒。

它火在哪

一是連莊本身就是新聞：Trending 日榜通常一天換一批名字，能連拿三天第一的專案不多，上一波做到這件事的是 auto-ontology。二是數字結構很健康：增幅三天從 19.99% 滑到 12.87%，看著像在退燒，但絕對新增每天都穩在三千上下（+3,324、+3,111、+2,842），絕對榜也是三天第一——新進來的人沒變少，只是基數變大了，分母一漲、增幅自然往下掉。三是敘事還沒講完：昨天講的 agent-ready 還在發酵，今天又多了一個可講的點——連文件同步都寫成契約，這種「把紀律寫進倉庫」的做法本身就很對開源社群的胃口。

值得學什麼

「文件同步」不要靠自覺，要靠契約。Astryx 把「架構改了、文件必須跟著改」寫在 README 頂上，當成倉庫的同步契約。回頭看我們自己的工具站：builder 腳本一改，說明常常慢半拍，復核流程改了、檢查清單還停在舊版——問題不在誰偷懶，在於沒有一條「改程式就得改文件」的硬規矩。這個做法成本幾乎是零，抄起來最划算。第二，發布第一天就要全套就緒：文件、Storybook、線上試玩場、CLI、Discord 社群，Astryx 上線那天就全擺出來了，熱度來的時候接得住；反過來想，我們的工具站新功能上線時，是不是也該先把說明和試玩路徑備齊再推？

我們怎麼用：前兩期的三個偷法（配色收進 CSS 變數、共用片段做成範本、交辦文件寫到 AI 不問人也能跑）今天仍然有效，不重複。今天加一條現成的：給工具站立一條同款規矩——改 builder 腳本先改說明，說明跟不上就不算改完，寫進倉庫的 README 裡當契約。真想試它：找個有 React 19 的小專案跑 npm install @astryxdesign/core @astryxdesign/theme-neutral @stylexjs/stylex，用 CLI 列元件玩玩看；還在 Beta，別直接上生產環境。

HA-MCP：AI 管家連莊第二——這次的新看點是「技能要用的時候才取」

homeassistant-ai / ha-mcp · MIT 協議 · Python · 87 個工具 · 需 Home Assistant 2026.8.0 以上

插畫：技能不預先塞進對話，全部掛在 skill:// 書架上——AI 要用的時候才伸手取一本，閒置成本只有一張目錄。

一句話人話

昨天第二，今天還是第二。讓 Claude、ChatGPT 開口指揮全屋家電的 HA-MCP 連莊了：一天 +640 星、增幅 9.55%，總星 7,343，兩天合計新增 1,432 星。

它到底是幹嘛的

基礎介紹見上一期（2026-11-10）：給 Home Assistant 用的 MCP 伺服器，87 個工具，裝進 HA 裡跑，AI 直接讀設備狀態、按開關。今天補兩個上一期沒講的新看點。第一，內建 Agent Skills：技能以 skill:// 資源的形式掛在 MCP 伺服器上，客戶端要用的時候才取，不用不佔上下文；只支援工具的客戶端也可以透過 ha_get_skill_guide 這個工具去讀技能說明。第二，檔案與 YAML 編輯工具：另外有一組特權工具，能讓 AI 直接改 HA 的設定檔和模板——但預設是關的，要開 beta 開關才啟用，正式用之前得先想清楚權限。

它火在哪

一是連莊第二天，數字沒掉隊：昨天 +792 星（13.58%），今天 +640 星（9.55%），增幅回落但絕對新增還在六百以上，榜上同類專案裡沒有對手。二是它踩的兩個風口都還在漲：MCP 已經是 AI 接工具的通用語言，Home Assistant 又是自架智慧家庭的事實標準，兩邊的使用者繼續疊加。三是官方味越來越重：整合進了 Home Assistant 2026.11 的 Marketplace 預設目錄，裝起來沒有「第三方野路子」的疑慮——上一期講過，今天再強調一次，因為這正是它能連莊的原因之一。

值得學什麼

「技能要用的時候才取，別預先全塞進上下文」。ha-mcp 把技能掛成 skill:// 資源，閒置成本只有一張目錄清單，AI 需要時才取全文。這個思路昨天講「工具太多要給搜尋方法」，今天是同一條線的下半句：我們的復核清單、工具站的 builder 說明越來越長，與其一次全餵給 AI，不如先給目錄、按需取用。第二，特權能力預設關閉：能改設定檔的工具要開 beta 開關才啟用——能力分級、預設最小權限，這個習慣搬到我們自己的流程上也一樣：會動到資料的步驟，先預設關著、要用人再開。

我們怎麼用：家裡如果有跑 Home Assistant（樹莓派或備用小主機就能跑），這是現成的 AI 遙控器：裝整合、貼網址進 Claude，睡前一句話關全屋燈，比寫自動化腳本快得多。就算家裡沒裝，README 裡的「技能按需取用」也值得偷進復核流程——檢查清單先列目錄，執行時再取全文，別一次全餵。安全提醒照上一期的說法：連線網址是秘密網址，別貼到公開地方；遠端存取用不到就保持關閉，區網內用就夠了；檔案編輯工具預設是關的，沒想清楚權限之前別開。

Sure：花了一百萬美元做出來的理財 App，商業上死了，開源社群把它救活了

we-promise / sure · AGPLv3 協議 · Ruby · 自架個人理財 App · Maybe Finance 的社群分支

插畫：Maybe 停更開源之後，社群 fork 出來改名 Sure 繼續維護——同一份程式，換個名字、換一批人，接著往下走。

一句話人話

一個死過一次的理財 App，被社群接手復活了。Sure 一天 +1,079 星、增幅 9.1%，總星 12,933——還是今天全場絕對新增第二，只輸給 Astryx。

它到底是幹嘛的

一個可以自己架在伺服器上的個人理財 App（Ruby 寫的，AGPLv3 開源）。故事要從前身說起：Maybe Finance 團隊 2021–2022 年花了近一百萬美元（人力、數據供應商、基礎設施加起來）做出一個功能很全的理財 App，連「問真人理財顧問」都包在訂閱裡；但商業上沒跑通，2023 年中停更、把程式開源，託管版短暫上線過一次也沒撐住。現在這個倉庫就是社群接手維護的分支，改名叫 Sure 繼續往下走。功能上是個全套的記帳管家：瀏覽器、macOS 桌面、手機 App、API、LLM agent 都能連進來；儀表板看現金流、淨值、支出，內建 AI 助手可以直接問它「這個月存了多少」；自架用 Docker 就能跑，也有 Render 一鍵部署（分不帶 AI、帶 OpenAI、接外部助手三種），還能上 PikaPods、Hostim。開發者想玩的話，rake demo_data:default 灌一份演示資料就能起步。

它火在哪

一是「復活」本身就是故事：一個燒掉一百萬美元的產品，商業上判了死刑，開源之後被社群撿回來接著做——這種劇本在開源圈永遠有人買單。二是自架理財正當紅：不想把收支、資產全交給第三方 App 的人越來越多，一個能自己架、資料在自己手裡的理財 App，剛好踩在這個需求上。三是數字紮實：一天 +1,079 星，絕對新增全場第二，fork 數 956 個——fork 多說明不只看熱鬧，是真有人拿去架、拿去改。

值得學什麼

開源分支的體面做法，值得記下來。Sure 的 README 專門寫了一節「分支與署名」：保留 AGPLv3 授權、說清楚自己是 Maybe Finance 的分支、聲明與原公司無關；「Maybe」是原公司的商標，分支不能用，所以改名 Sure——連改名的原因都寫明白了。以後我們 fork 別人專案時，照這個清單做就不會踩雷。第二，效能問題公開攤開來修：README 直接掛了一個公開的效能儀表板，跑得慢的請求連堆疊追蹤都公開，邀請大家一起來修——把短板亮出來，反而更容易拿到幫手。第三，AI 助手不是噱頭，是查帳的入口：對著結構化資料問一句話就能查帳，這個模式比「再做一個圖表」更接近人真正想用的樣子。

我們怎麼用：如果想自己管帳、不想把財務資料放第三方，Docker 自架一個 Sure 是現成的路（rake demo_data:default 先灌演示資料試手感，滿意了再接自己的帳）。就算不裝，也有兩個思路可以直接偷：第一，「用一句話問帳」可以學進工具站的復核流程——與其翻表格找數字，不如讓 AI 對著結構化資料直接回答；第二，效能儀表板公開的做法值得學，工具站哪個環節慢、慢在哪，攤開來反而好修。提醒一句：Sure 是記帳／資產追蹤工具，僅供研究、不是投資建議；它本身也沒有交易功能，別拿計畫資金去試任何投資操作。
