auto-ontology：連莊第一，絕對新增也是第一——「先對定義」不是一日新聞

NVIDIA / auto-ontology · Apache-2.0 · Python（後端）＋ Next.js 前端 · 昨日基數 4,556 星

插畫：auto-ontology 兩天對比——增幅數字變小了，但每天新加入的人反而更多，這叫放緩，不叫退潮。

一句話人話

昨天講過的「AI 查數之前先認證定義」那套，今天第二天登頂：核心沒變，變的是數字——每天新加入的人比昨天還多 654 個。

它到底是幹嘛的

昨天的完整介紹今天不再重抄，只補一句給新讀者：這是 NVIDIA 的 Python 框架，幫企業資料建一層「語意圖譜」——詞彙、事先審過的 SQL 屬性、表間關係三種定義先由人認證，之後 agent 每次查數都照著同一套定義寫 SQL、附算式交出來，答不出就直說。部署是 Docker Compose 或 Helm 上 Kubernetes，推理走 NVIDIA NIM 端點，需要一把 NVIDIA API key；Quickstart 是 git clone https://github.com/NVIDIA/auto-ontology.git、cp .env.example .env、docker compose up -d --build，打開 http://localhost:3000 就能用範例資料庫問問題。

它火在哪

第一，兩天都是斷層第一：昨天 +2,053 星、增幅 72.16%，今天 +2,707 星、增幅 59.42%，總星從 4,898 衝到 7,263，兩天漲了將近一半。第二，今天的絕對新增也是全場第一，比第二名多 534 星——增幅榜第一和絕對榜第一是同一個名字，這種雙料第一不常見。第三，維護沒停：專案頁顯示提交已到 1,366 次，昨日仍有提交（API 顯示最後推送 2026-11-05），fork 574 個，不是漲完就丟著的專案。值得多看一眼的是，它自己也在倉庫裡放了一個 skills/ 目錄——NVIDIA 也在用「agent skills」這種形式教 agent 怎麼用自己的工具，跟今天第二名的玩法是同一條路。

值得學什麼

連莊本身就是驗證。一天爆紅可能是跟風，兩天都斷層第一，說明它打中的痛點——「查數查得快沒用，查得對、還能交代出處才算數」——是真有一群人在等解法。昨天講的「定義先認證、答案附算式」今天照舊值得偷；今天再補一個觀察：一個好工具現在連「怎麼教 AI 用它」都一起打包了，README 裡的 agent skills 和 MCP 接法不是附贈品，是產品的一部分。

我們怎麼用：昨天的三條偷法今天照舊，不再重複展開：給工具站建一本小小的「指標字典」、同一指標只留一種算法、關鍵數字附上可核查的算式或來源。今天多補一條：去翻它倉庫裡的 skills/ 目錄，看看一個資料工具是怎麼寫「教 agent 用我」的說明書的——以後我們寫給 Hark 或寫進排程的任務說明，也可以照這個格式：先講能幹嘛、再給命令、最後寫清楚什麼時候該說「答不出來」。整套堆疊要 Docker、Postgres 還要 NVIDIA API key，別直接搬上工具站；真想試，只在測試環境用範例資料庫跑一圈就好。
🥈 第 2 名 · 昨日 +674 ⭐ · 增幅 28.55% · 新面孔

skills：不賣模型，賣「教 AI 做圖做片」的一大包說明書

scenario-labs / skills · MIT · Python（倉庫語言） · 昨日基數 2,361 星

插畫：skills 不生成任何東西，它只教你的 AI 助手怎麼生成——先報價，再動手。

一句話人話

一大包「教 AI 做圖、做片、做 3D」的說明書：裝進 Claude Code、Cursor 這些寫作助手裡，助手就知道該調哪個模型、做之前先報價、怎麼讓同一個角色在不同圖裡長得一樣。

它到底是幹嘛的

這是 Scenario 公司的 agent skills 合集，遵循 Agent Skills 格式（一個技能就是一份 SKILL.md）。分兩大包：第一包走 Scenario MCP 伺服器，教 agent 用 Scenario 生成圖片、影片、音訊、貼圖、天空盒、3D 模型和客製訓練模型，覆蓋遊戲、娛樂等創意場景，賣點寫得很直白——選對模型、花錢之前先報價、角色和品牌在多張圖裡保持一致；第二包是「專家工具」，一組組技能驅動裝在本機的創作軟體和遊戲引擎（ZBrush、Blender、Maya、Unreal、Unity、Godot、Roblox Studio），做法是把專家教學、研討會和官方文件提煉成 agent 能照著做的步驟。安裝是 npx skills add scenario-labs/skills（會開選單挑），或只裝一個：npx skills add scenario-labs/skills --skill scenario；接 MCP 是 claude mcp add --transport http scenario https://mcp.scenario.com/mcp，要登入 Scenario 帳號（OAuth）或用 API key。倉庫 2026-08-12 建立，MIT 協議，昨日仍有提交，fork 266 個，文件和 INSTALL.md（按職業和目標分組的安裝命令）都齊全，不是丟上來就跑的演示。

它火在哪

第一，數字是真的陡：昨日基數只有 2,361 星，一天 +674 星，增幅 28.55%，是今天增幅榜第二，也是本期唯一的新面孔。第二，它踩在正熱的點上：最近上榜的專案裡，Hallmark、Impeccable、今天的第一名 auto-ontology，都在用「skills」這種形式教 AI 幹活——「說明書本身就是產品」正在變成一種共識，這包 skills 等於把這個共識做成了現成的貨架。第三，覆蓋面寫得很實在：支援 70 多種 agent，技能按用途分了入門、找方向、圖片、遊戲美術、影片音訊好幾組，不是只有一個範例撐場面。

值得學什麼

「先報價再花錢」是個值得偷的設計。生成式工具最讓人肉痛的不是單價，是不知道這一按下去要花多少——這包 skills 把「報價」寫進流程裡，生成之前先把成本攤開來，貴不貴由人決定，不是事後看帳單才嚇一跳。另一個值得偷的是 Agent Skills 這個格式本身：一份 SKILL.md 就是「教 agent 做一件事」的最小單位，有安裝命令、有步驟、有檢查點，寫一次，到處都能裝。INSTALL.md 按職業分組（2D 美術、製作人……）的做法也聰明：不讓人從一百個技能裡自己挑，而是先問「你是幹嘛的」。

我們怎麼用：先把話說老實：對工具站來說，它沒有直接用途——工具站是靜態頁面，不需要生成圖片影片，報告插畫也是手寫 SVG，沒必要為此開一個付費的 Scenario 帳號。真正要偷的是兩件事：第一，Agent Skills 的格式可以直接拿來寫我們自己的工作說明——以後給 Hark 派任務、或把排程流程寫成文件，都照 SKILL.md 的樣子寫：先講能幹嘛、再給命令、最後寫清楚檢查點和什麼時候該停手；第二，角色一致性那套做法（scenario-consistency、identity-library 這兩個技能）跟我們做自拍時的「臉部鎖定」是同一個思路：先把角色特徵寫成一份檔案，每次生成都對著它驗，不合就重來。真想動手試，先只裝一個技能（npx skills add scenario-labs/skills --skill scenario）、接上 MCP 看一眼流程就好，別為了試格式就去儲值生成額度。

DiscImageStudio：光碟刻畫還在漲，只是基數變大了、增幅自然回落

JiaFeiMiao-K-Cat / DiscImageStudio · GPL-3.0 · C# · Windows 桌面版＋ Linux／macOS 實驗性 CLI · 昨日基數 6,275 星

插畫：DiscImageStudio 還在出貨——提交數一天多了 16 次，增幅回落只是因為昨天基數已經不小了。

一句話人話

前天講過的光碟刻畫工具，今天第三次出現在榜單附近：盤面還是那張盤面，變的是數字——增幅從 37.52% 回落到 15.57%，但一天還是多了 977 顆星。

它到底是幹嘛的

給昨天、前天沒看的人補一句：這是一個多平台的光碟盤面可見圖像生成與刻錄工具——你給它一張圖，它算出一組符合光碟物理規則的數據，刻完之後盤面肉眼看得到這張圖，而且這張盤還能照常存檔案。CD 支援帶格式頭的 WAV 音軌加配套 CUE（也支援 RAW 音軌），DVD 匯出 ISO，藍光支援純繪圖與 UDF 2.01 檔案；Windows 下載 win-x64.exe 就能跑（自帶 .NET 執行環境），Linux 或 macOS 下載對應 CPU 的實驗性 CLI，解壓後跑 ./disc-image-studio --help，CLI 範例是 ./disc-image-studio cd-generate --input picture.png --output sample.wav --sectors 2。前天已展開講過的標定三段流程（粗標定、邊界標定、精細標定）和安全須知今天照舊：即時刻錄只用可報廢的測試介質。

它火在哪

第一，數字還在漲：昨日基數 6,275 星，一天 +977 星，總星 7,252，絕對榜第三。增幅從前天的 37.52% 回落到 15.57%，這是分母變大的正常現象——跟昨天 agent-desktop 的故事一模一樣，單看增幅會以為它涼了，兩個數一起看才知道它還在漲。第二，出貨沒停：提交數從前天的 72 次漲到 88 次，版本到了 12 個，昨日也有提交，不是漲完就丟著的專案。第三，它是今天主榜裡唯一一個跟 AI 沒關係的專案——不靠模型、不靠 agent，靠的是把光碟物理層的約束寫成規格，這種「硬派手藝」在滿屏 AI 專案裡反而顯眼。

值得學什麼

出貨節奏本身就是漲勢的一部分。從 2026-08-23 建立到現在兩個多月，12 個版本、88 次提交，平均兩三天就有動靜——一個專案能不能一直出現在榜單上，不只看點子有多酷，還看它是不是一直在動。前天講的「把限制寫成規格」今天照舊值得偷；今天再補一個：版本號和提交記錄就是信任狀，別人判斷要不要裝一個工具時，先看的就是「最近有沒有人在動它」。

我們怎麼用：前天的結論今天照舊：對工具站來說它沒有直接用途——沒有刻盤需求就不用裝，別為了追星而裝一個用不上的工具。真正要偷的還是那兩件事：數據管線先寫約束再跑（某個指標的基期門檻、某個欄位的合理範圍，先寫成規則擋在入庫前面）；任何「理論值 vs 實測值」對不上的地方，都照標定流程走——先量、再修正參數、再驗一次，別憑感覺調參數。今天多補一條：工具站自己的更新節奏也可以學它——小步、頻繁、每次都有據可查，久了別人自然信得過。如果真的有懷舊刻盤或實體備份的需求，先用匯出 ISO／WAV＋CUE、再用熟悉的刻錄軟體刻；即時刻錄只拿可報廢的測試盤試，正式盤別拿來練手。
