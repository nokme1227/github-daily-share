一句話人話

開源的 AI 影片剪輯桌面工具：貼一個長影片連結，選好要發的平台，它自動剪出短影片，連字幕、封面和發文文案一起給你。一天 +640 星、增幅 5.01%，總星 13,412——前兩天分別是 +983 星、+689 星，三天新增合計 +2,312 星，fork 數也從昨天的 2,072 個漲到 2,124 個。

它到底是幹嘛的

核心流程前兩期講過了，今天只補 README 裡最值得看的三處，都是發稿前剛對照原文核實過的。第一，README 開頭不是功能清單，而是「真實成片」：精選 6 條、展開還有 10 條，豎版分訪談式與滿屏播客式、橫版保留原畫幅，每條都標了平台、語言和片長，還能直接點開看完整成片，文末註明原片版權歸原作者、僅作效果展示。第二，挑段的規矩寫得很死：每個平台按評分自動生成至多 10 條合格片段，其餘列為備選，點「生成這條」再製作；每條都帶封面、標題、簡介、話題和 ZIP 發布包——不是一次倒出一堆，合格才算數，不合格的先放著。第三，資料邊界寫得比功能更直白：剪輯、取景與渲染在本機完成；用雲端分析會送出相關字幕與文案，畫面理解或參考幀生圖會送出抽樣畫面，雲端轉寫會送出音訊；用本地分析與本地轉寫就不需要對應的雲端 API。模型自己選：雲端 API、Ollama、LM Studio 都行，桌面版還能先看內建的示例項目，不用 API Key。費用表仍是原來那三條實測（README 自己註明不是同一輸入的速度對照），本期未變，就不再重貼數字了。

它火在哪

一是連漲第三天，而且一天比一天「險」：+983、+689、+640，增幅從 8.80%、5.67% 滑到 5.01%，幾乎是貼著門檻線進來的——但貼線也是過線，連續三天有人裝、有人用，才撐得住這種走勢。二是它換了說服方式：前兩期我們講的是「三個入口、一個版本號」「費用口徑寫清楚」，今天 README 開頭那 16 條真成片才是更硬的證據——能剪出什麼樣子，先給你看，看完再決定要不要裝。三是新入口還在長：MCP 新增 start_quick_output／get_quick_output_status，一行安裝也寫進了 README：uvx autoclip-mcp，再加 npx skills add zhouxiaoka/autoclip——agent 想接它，不用先讀完一整份文件。

值得學什麼

最值得偷的是 「先放證據，再列功能」：README 的第一屏不是「我們支援多少平台」，而是 16 條能點開看的成片——寫我們自己的工具介紹時也一樣，先給一個能點開、能驗證的結果，再談功能清單，讀者才不用先信你、再試你。另一招是 「合格名額寫死，備選另外放」：至多 10 條合格、其餘當備選，寧可少給、不要濫給——我們工具站的榜單也有同樣的毛病：名額湊滿容易，湊滿之後的可信度難保；先定「不夠格就空著」，榜單才一直值錢。還有 「資料邊界先講清楚」：什麼會送上雲、什麼留在本機，一句一句寫明——這種話寫在前面，事後才不用一遍遍解釋。

我們怎麼用：手邊有訪談、播客或課程長片想剪短片的人，先從桌面版的示例項目看效果，不用 API Key；想接進流程的話，CLI 的 autoclip produce talk.mp4 --srt talk.srt --platform douyin --portrait-style podcast --json 照舊可用，已有字幕可用 --srt 跳過轉寫，版本以 autoclip --version 為準。只剪自己有權使用的素材，別拿別人的成片去發。對工具站來說，今天最值得帶走的是那句「先放證據」：以後報告裡的新工具，也先給一個能點開驗證的結果，再寫它有多好用。
